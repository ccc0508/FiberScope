# FiberScope 诊断评测 v1

使用原始轨迹评估检索、SQL 执行和跨来源取证。保留原有四组端到端答案评分。这里统计的是特定环节的表现，新增指标单列，不参与原有总分加权。六道非论文题继续使用行为验收。

## 文献检索

`chunk-qrels.json` 给 24 道论文题标注了 286 个「题目、相关原始块」对。标注以八篇论文的冻结块库、题目和论文证据位置为依据。直接支持某项要求的正文、表格或图像所在块可以入选。同题的等价块如果有不同的块 ID，按块分别计数。标注是本轮初评，尚未经过独立领域专家复核。所有召回率均相对于这份标注；漏标会把实际相关块误算为无关。

- 每次成功的 `search_literature` 从 `retrieval.vector_search` 读取候选，从 `retrieval.select_seeds` 读取经过重排和最终选择的主命中。上下文补入的相邻块、章节阅读和直接读表另走其他工具，不进入这两组集合。
- 同一题同一阶段多次检索，对原始块 ID 求并集。精确率为命中的已标注相关块数除以实际返回的唯一块数；召回率分母是该题标注的全部相关块数。跨题累加分子、分母，得到微平均。同一块在不同题的相关性分别判断。
- 另外报告同预算对照 `vector_at_seed_limit`，对每个向量查询分支取本次主命中名额 K，再按题去重。它用于判断保留相近数量的块时，排序与筛选是否有收益。若未来使用多个向量分支，此对照为每个分支各取 K。
- 未成功调用向量检索的题单列。成功检索且返回零块，精确率无定义，召回率记零。缺少配对阶段的轨迹不能进入任一侧比较。固定 metadata.sqlite3 的哈希保证两阶段共用同一版块编号；换块库后应重新标注。

## SQL

- **执行成功率** = 成功取得结构化 SQL 结果的次数 / 实际交给 `query_experiment_data` 的次数。SQL 工具校验、预检或执行失败均计入分母。Agent 调度层提前拦截的提案，以及读取目录的调用，单独看轨迹。返回空表属于成功执行。
- **结果集正确率** = 满足该题全部参考结果的题数 / 要求取数的题数。当前 20 题中有 17 道取数题。对照同次冻结的 `sql-references.json`，核对原始结果；正文措辞、换算和推断由答案评测负责。
- 对参考 SQL 或已审核的等价查询按指标列取值；支持多次查询组合，当需要关联两个单行结果时，校验关联键。默认按含重复行的无序集合比较，SQL02、SQL03 检查顺序。空表、NULL、零分别处理。整数精确匹配，连续量允许绝对误差 0.01，SQL13 为 0.0001。截断结果不能直接判对。
- 新 SQL 无法由已核对的映射自动判定时，导出复核包，检查对象、条件、聚合和真实返回行，允许等价写法。使用 `--review` 传入以题号为键的对象，每题含 `fingerprint`、布尔值 `correct` 和 `reason`。已审题正确率和完整取数题正确率分别输出；仍有待审或缺题时后者为 null。

## 综合题

`mixed-needs.json` 按题列出应取得的证据，20 题共 51 项。含不同论文、实验数据库、表或图等可独立验收的要求。MIX20 需要先澄清，没有强制取证项。

- **工具调用准确率** = 判断为合适的子 Agent 业务工具提案数 / 全部这类提案数。查看所选工具、论文或样本、参数、调用时机与任务目的，接受等价路径。错误对象、无效参数、无意义重复以及违反当时调度规则的调用扣分。合理补查得到空结果也可判对。Planner 路由、模型调用和子任务提交不作为业务工具调用。
- **必需证据完备率** = 最终综合作答实际收到且足以支持的必需证据项数 / 该题全部必需证据项数。引用号出现在回答里，或工具曾查到一条结果，均不足以直接判定完备。复核最后一次 `synthesis_review` 的输入，表图题还要核对是否真正读过图及对应的观察。未走到综合作答时，所需证据交付数为零。零需求题不增加该指标分母。
- 使用 `--packets` 导出题目、按顺序排列的工具提案、证据要求、最终实际收到的证据及子任务汇报。包内 `e1` 等键按综合作答输入顺序编排，仅用于评审定位。以 `mixed-v7-review.json` 为逐项判断示例。每个提案附布尔判断与理由，每项需求填写支持它的来源键和理由；没有充分支持则给空数组。程序检查覆盖数、来源是否合法及成功状态，并校验轨迹指纹。新运行需要重新复核。全组按各题分子、分母累加，待审题数在 `status_counts` 单列。

## 复现冻结基线

在项目根目录运行，参考快照及原始运行记录在本地忽略目录中。生成这些诊断不会调用答题模型或裁判 API。

```powershell
$b = ".rag-data/evaluations/specialists-three-suites-20261107"
$o = "output/diagnostic-metrics-v1"
python -X utf8 scripts/diagnostic_metrics.py literature --run "$b/rag-full-v7-20261109" --out "$o/literature.json"
python -X utf8 scripts/diagnostic_metrics.py sql --run "$b/sql-full-v7-20261109" --out "$o/sql.json" --packets "$o/sql-packets"
python -X utf8 scripts/diagnostic_metrics.py mixed --run "$b/mixed-full-v7-20261109" --review data/agent-evaluation/diagnostics-v1/mixed-v7-review.json --packets "$o/mixed-packets" --out "$o/mixed.json"
```

新综合题运行先省略 `--review` 导出复核包。填写与新轨迹匹配的判定文件后，再运行同一命令并加上 `--review`。可提交的精简结果见 [baseline-v7.json](baseline-v7.json)；单题检索命中与漏召回块、SQL 各参考结果的判断及综合题分子分母可在输出 JSON 的 `cases` 中查看。
