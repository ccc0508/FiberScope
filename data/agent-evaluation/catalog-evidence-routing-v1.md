# 依据需求路由、逐项证据充分性与一般知识兜底

## 实现

Planner系统提示词新增主题微缩目录。只纳入当前活动库中实际存在的文献编号；八篇已知论文的标题、作者标签与主题存于backend/literature_rag/application/routing_catalog.json，按文献ID匹配。新论文仍自动显示其真实标题/文件名，主题为空，不冒用旧摘要。目录不含性能数值、因素排名或结论，不是引用来源。后续新增论文的主题描述需维护；此次不自动调用模型生成摘要。

路由根据完整问题所需依据决定：基础定义、文本转换可direct；科研机理、条件解释、比较排名、研究数据合并走literature，不要求用户写作者名。both仅用于项目数据库与论文共同需求，论文里的实验不等于本地SQL任务。目录未匹配不证明库内不存在，科研问题可以有限查库。

沿用原文要求清单与一次有限补查；coverage新增partial与gap，分别保存已支持的事实和未解决部分。程序检查真实已交付引用、文献ID、结果与缺口是否填写，生成sufficient/partial/insufficient汇总；空清单不算充分。部分项仍可触发一次补查，不增加新预算。程序不验证科学语义或保证模型填报真实，正确性仍依赖模型核查。

父级汇总保留已验证内容及各项缺口；对解释性问题可补充“**一般原理解释（非本次文献证实）**”，说明适用条件与不确定性。不能用一般知识填补论文表值、作者结论、实验数据或论文身份，也不能把无关引用贴给兜底解释。对纯论文事实请求只报告缺口。不会退回Planner重答，也不会丢掉部分正确证据。

删除共享目录前缀中“通用知识直接回答/实验问题用数据库工具”的越权指令，改为遵守当前角色与工具权限。单Agent仍由自己的主提示词决定一般知识处理。

## 验证与限制

49项单元及回归测试通过，涵盖目录仅包含活动文献、未知文献身份保留、Planner收到目录、部分证据缺口、未交付引用不合格、空清单、一次有限补查及父级收到证据与缺口。测试模型为模拟，验证程序约束，不证明自然语言路由稳定性。

另外进行了6个真实模型路由冒烟请求，独立上下文，无检索或SQL执行，结果见catalog-routing-smoke-20261108.json。它只验证入口决策，不验证检索充分性、最终兜底解释质量或最新70题能力；没有因此更新旧评测分数。后续应固定问题与配置验证误路由率、部分证据保留和兜底无来源事实扩张。

版本标识specialists-v4-evidence-routing。未改回答模型、预算、检索索引或SQL权限，未部署服务器。
