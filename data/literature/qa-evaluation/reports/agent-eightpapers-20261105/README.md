## 主要发现

- 003：三项提升数值列对，但不肯确认耐破/撕裂对应50%配比；实际收到的MinerU中文结论恰好丢失50%，原PDF明确。因此存在上游解析缺损，不能仅归因回答能力。
- 004：没有回答棉浆耐破及马尾松配比趋势。没有成功调用读图工具；原PDF正文与图3可回答。
- 017：一次搜索只拿到Morais参考文献条目，未取得表1粗度单位，尚有搜索额度也未补查。换算本身正确。
- 019：一次搜索未拿到Ayaliew，拿Uddin替代指定论文展开比较；缺失合成数据和新增验证抗张反例。是来源识别与缺口处理失效。
- 024：三篇比较遗漏损伤D/T₀链条、合成数据属性，未确认Uddin目标单位。
- 008：内容方向正确，但重新编排引用编号；实际[6]来自Uddin，却说成Ayaliew结论。引用编号稳定性仍需修复。
- 013、018、022等：额外扩写引入相关对象错配、跨定义尺度比较及bulk误译为紧度。Jev并未全部发现这些问题，校准记录已说明依据。
- 025、026：无需检索的路由正确，但违反“一句”要求，多加解释；不能当格式完全遵循。

## 配置与统计限制

- 答题：deepseek-flash，thinking=false；MinerU＋qwen3-vl-embedding，8篇冻结语料。
- Agent预算：最多6次模型调用、8次工具调用、2次搜索；每轮最多一个工具；总时限240秒，预留45秒；输出8192 token，文本上下文160000字符。一次全文复核，非旧结构化多轮纠错。
- 每题输入相同作答说明＋单题，不含gold答案。非论文题也走同一Agent入口。
- Jev：typesafe/jev-1.14，OpenRouter原生Decisions，无旧评分上下文。使用题目相关原始PDF页、实际检索证据及评分标准。未给Jev图像像素；本轮没有任何成功的view_image调用，不能由本轮证明视觉能力。
- 核查单元沿用原有适配器：保留Markdown段落/列表/表格上下文，**不是逐句原子事实**。一个段落可以含多事实。事实/引用率对此粒度敏感，报告同时保留分母与全文，不能将68.55%简单解释为逐句正确率。
- FS8-002原gold K4要求“不能泛化至所有浆种”，但题面没有问泛化；校准将其记N/A，不因未回答额外问题扣分。原始gold与Jev结果保留。后续对照应采用同一修订口径。
- 单轮结果不估计稳定性；新30题不能直接与旧32题总分比较。
- `routing_ok=29`只是检索账本中所需文献身份覆盖的代理指标，不等同证据齐全；017命中参考文献条目仍会通过这个粗指标。
