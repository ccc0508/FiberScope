# 植物纤维数据库系统阶段汇报

## 一、工作目标

本阶段的主要任务，是将分散在多份 Excel 中的针叶木浆、阔叶木浆、针阔复配实验数据和再生纸浆循环实验数据，建立为结构统一、数据可靠、来源可追溯的数据库，并为后续可视化分析平台提供稳定的数据基础。

整体流程为：

```text
原始Excel → 数据预检与标准化 → PostgreSQL正式数据库 → 分析视图 → 后端接口 → 可视化平台
```

## 二、数据整理与关键规则

当前正式数据来源由两部分组成：

- 8份核心实验 Excel，包括针叶木、阔叶木的打浆度、纤维特性和纸张性能数据，以及0110版复配纤维和纸张数据；
- 1份再生纸浆循环实验工作簿 `数据汇总(1).xlsx`，以独立数据集形式保存，不与61个最终均值样本混合。

两份旧复配工作簿不进入正式数据库。复配实验统一使用：

- 针叶木浆：14000 r、41.0°SR；
- 阔叶木浆：8000 r、40.6°SR。

复配两端不重复创建样本：`zk010` 复用阔叶木8000 r样本，`zk100` 复用针叶木14000 r样本，中间9个比例点创建新的复配样本。

核心实验保留全部12项纤维特性和9项纸张性能。透气度单位暂按 `μm/(Pa·s)` 标记，耐折度单位暂不推断。再生纸浆循环数据逐行保留10档长度分布、12项纤维特性和3项纸张原始强度；4行长度分布合计偏离100%超过1个百分点的数据只作复核标记，不自动归一化。

## 三、数据库设计与实现

数据库选用 PostgreSQL 18.x，数据库名称为 `plant_fiber_db`，业务数据统一存放在 `fiber` Schema 中。

当前系统共有11张正式表，由8张核心表和3张再生纸浆扩展表组成：

| 表 | 主要作用 |
|---|---|
| `material` | 保存针叶木浆和阔叶木浆两种基础原料 |
| `experiment` | 定义针叶木打浆、阔叶木打浆和针阔复配实验 |
| `sample` | 保存全局唯一的物理样本 |
| `experiment_sample` | 保存样本在不同实验中的编号和显示顺序 |
| `sample_component` | 保存原料比例、打浆转数和打浆度 |
| `fiber_measurement` | 保存12项纤维特性 |
| `paper_measurement` | 保存9项纸张性能及均值说明 |
| `data_source` | 保存核心数据文件名、工作表和原始行号，实现数据追溯 |
| `recycled_dataset` | 登记再生纸浆循环实验工作簿、版本和文件散列 |
| `recycled_data_block` | 保存14个连续数据块及已确认的来源元数据 |
| `recycled_cycle_observation` | 保存131条逐行循环观测和Excel原始行号 |

数据库通过主键、外键、唯一约束、数值检查和触发器保证样本不重复、比例合计为100%，并确保复配样本使用规定的打浆条件。再生纸浆数据独立建模，避免把逐行循环观测误当作最终均值样本。

## 四、数据入库与验收结果

正式入库前，程序会检查文件版本、表头、行数、数值格式、样本编号、复配比例、端点一致性、工作簿散列和再生纸浆数据块结构。只有全部阻断检查通过后，数据才会在事务中写入数据库；任一环节失败时整批回滚，不留下不完整数据。

核心实验数据入库结果如下：

| 数据对象 | 数量 |
|---|---:|
| 唯一物理样本 | 61 |
| 实验展示点 | 63 |
| 样本组分记录 | 70 |
| 纤维特性记录 | 61 |
| 纸张性能记录 | 61 |
| 原始来源记录 | 178 |

再生纸浆循环数据入库结果如下：

| 数据对象 | 数量 |
|---|---:|
| 数据集 | 1 |
| 数据块 | 14 |
| 逐行观测 | 131 |
| 数据块×循环汇总点 | 47 |
| 质量复核记录 | 4 |

V004、V005、V007和V010验收结果均为 `PASS`。同时完成了最新数据库基线备份，并通过归档可读性和SHA-256完整性检查。

## 五、面向可视化的分析视图

为了避免可视化平台直接组合多张底层表，当前建立了8个分析视图：

| 分析视图 | 用途 |
|---|---|
| `v_sample_overview` | 查询样本类型、复配比例和打浆条件 |
| `v_fiber_paper_analysis` | 综合分析12项纤维特性和9项纸张性能 |
| `v_beating_analysis` | 分析打浆转数、打浆度与性能的变化关系 |
| `v_blend_analysis` | 分析针阔比例与纤维、纸张性能的关系 |
| `v_data_lineage` | 定位到核心数据的Excel文件和原始行 |
| `v_recycled_cycle_detail` | 查询131条再生纸浆逐行观测 |
| `v_recycled_cycle_summary` | 查询47个数据块×循环均值点 |
| `v_recycled_data_quality` | 查询4条需要复核的长度分布记录 |

后续可视化页面不会直接连接数据库，而是通过后端接口查询这些视图，从而保持数据口径一致并降低安全风险。

## 六、当前成果

目前已形成以下主要成果：

- PostgreSQL数据库、8张核心表和3张扩展表；
- 正式数据库设计说明；
- 覆盖11张表、114个字段、229条入库映射和30条验收规则的数据字典；
- V001至V010数据库迁移与验收脚本；
- 两套Excel只读预检和事务化入库程序；
- 预检报告、正式入库SQL及数据库基线备份；
- 8个面向可视化平台的分析视图。

## 八、汇报总结

本阶段完成的工作不只是将Excel导入数据库，而是建立了一套包含数据范围确认、统一编码、规范化建模、自动预检、事务化入库、约束校验、来源追溯、质量标记、备份恢复和分析视图的数据管理流程。

目前数据库已经形成“8张核心表 + 3张扩展表”和“5个核心视图 + 3个扩展视图”的完整结构，具备数据完整、来源可追溯、权限受控和支持可视化查询等能力，可以进入后端接口和可视化平台开发阶段。
