# 文献问答有限纠正流程：实现与验证

日期：2026-11-03。版本：`bounded-corrective-review-v1`。

后续 v2 实验及32题结果见[实验报告](QA_CORRECTIVE_V2_EVALUATION_20261103.md)。v2 未证明整体改善，默认保留本页描述的 v1；新增版本选择配置默认 `RAG_CORRECTIVE_REVIEW_VERSION=v1`。

## 本次实现

现有审校只输出编辑建议；空建议不能证明回答覆盖了用户需求。新模式在同一次 DeepSeek 审校请求中增加“需求—证据—回答”对应检查，将每项标记为：

| 诊断 | 程序动作 |
|---|---|
| covered | 保留回答 |
| edit | 已有证据足够，执行带来源依据的最小修订 |
| lookup | 当前摘录缺少明确所需信息，允许同篇论文内定向补查 |
| unresolved | 无可靠补查目标、证据冲突、仍缺信息或处理受限，保留未解决项 |

诊断来自用户问题和必要的科学解释限制，不读取评测答案或评分要点。同一道题可以同时包含直接修订和证据缺口；`lookup`也允许先执行已有依据的安全修订。

执行链路：首次检索和生成 → 第一次诊断及最小修订 → 按需补查一次 → 第二次诊断及最小修订 → 停止。第二次不能再要求补查，也不重新运行主回答生成流程。

### 补查范围和来源

- 由现有引用定位一篇已命中的论文，禁止跳到其他论文或互联网。
- 有明确目标时，通过已保存的分类与章节信息读取摘要、方法、结果、表格、图注或指定小节，再用缺口查询对候选重排。无章节目录或目标未匹配时，回到限定文献的向量检索。
- 位置不明确时，复用首次检索的候选，同时执行缺口查询。Chroma、表格行和图片召回均在候选截取之前按文献过滤；进入重排前再核对原文所属文献。
- 缓存与新候选先去重，候选最多50个；每个动作最多纳入2段新原文。不把旧问题的0.35筛选阈值当作补查的正确率阈值，不添加新的重排硬阈值。
- 补查不再次展开整个小节或递归读取关联块；返回完整的原始块，超长块记录预算阻断，不直接截断表格。
- 新读到的证据不等于有用或足够；由第二次审校检查材料、处理条件、测量口径及矛盾，并决定修订或保留未解决项。

### 执行上限

| 项目 | 上限 |
|---|---|
| 审校模型请求 | 2次；只有补查实际增加证据时才执行第二次 |
| 补查轮数 / 动作数 | 1轮 / 最多2个动作 |
| 补查阶段时间 | 最多40秒，同时为最终审校保留时间 |
| 单次补查 embedding / rerank 请求 | 最多20秒，并受剩余预算限制；不自动重试 |
| 审校请求 | 配置上限120秒；新模式按剩余问答预算缩短实际请求超时 |
| 审校输出 | 32768 Token，包含推理与输出 |
| 原文上下文 | 默认单段8000字符、总计24000字符 |
| 原图 | 默认4张、12 MiB；已保留证据的原图不会被新图片替换 |
| 整次问答 | 继续受现有300秒子进程总时限约束 |

预算不足时，优先移除未被当前有效回答引用的证据。当前回答所引用的原文全部保留；仍放不下则记录阻断。旧引用身份不变，新引用从原最大编号之后追加。因移除未引用证据可能产生编号空位，新模式允许严格递增且唯一的稀疏编号；旧生成阶段仍要求连续编号。未知引用、重复编号、错误引用等检查保留。

### 历史与页面

- 保存原稿、每轮需求诊断、建议编辑、接受/拒绝原因、实际原文和图像身份、补查查询、候选和排名、最终证据、耗时及已返回的Token用量。
- 保存供应商返回的用量；未返回或无法确定的金额记为未知，不按Token数编造费用。
- 历史图片备份同时覆盖初始与最终证据，避免未引用证据被移除后丢失首轮审校图像。
- 页面显示审校完成、仍有未解决项或审校未完整完成。未解决项可以展开查看。失败时保留最近一次通过结构校验的答案，并明确提示；不会标为“全部事实正确”。
- 全部修改仍经过引用格式和来源定位检查。这些检查不能自动证明语义正确。

## 真实模型验证

以下是功能验证，不是新一轮完整评测，也没有调用Jev或Luna。第14、18、32题复用先前保存的原始问题、回答草稿、证据文本和原图，不重新生成主答案；运行时未提供标准答案。三题各只执行一次新审校，未挑选多次中的最好结果。

| 输入 | 实际动作 | 人工检查发现 |
|---|---|---|
| 第14题 | 1次审校、0次补查，接受2项修订 | 加入相对含量和推测语气，但仍写成“纤维素分子链断裂”，没有解决原先关于链间作用与分子主链断裂的区别 |
| 第18题 | 1次审校、0次补查，接受1项修订 | 明确加入“峰面积相对百分比，不是绝对氢键数量或浓度”，原先缺少的口径限制得到补充 |
| 第32题 | 1次审校、0次补查，接受3项修订 | 改善相对含量、推测语气及摘录范围，但没有主动读取摘要，仍未指出摘要与正文数值不一致 |
| 明确缺少FT-IR方法的功能用例 | 2次审校、1轮方法区域读取、1次重排，补入2段原文 | 从仅有XRD表格、无法回答的输入，找到同篇论文的方法段，回答制样、分辨率、扫描次数和归一化条件；不需要新embedding请求 |

最后一项是刻意限制初始证据的链路验证用例，不属于32题评测集，不能用于提高总分。它验证程序确实会执行补查并把新原文送进第二次审校；前三题也说明诊断模型仍可能误判“已经覆盖”。

| 输入 | DeepSeek审校Token合计 | 整个纠正流程耗时 |
|---|---:|---:|
| 第14题 | 24,794 | 69.557秒 |
| 第18题 | 16,355 | 45.096秒 |
| 第32题 | 28,510 | 92.535秒 |
| 方法缺口用例 | 12,935 | 41.003秒 |

五次DeepSeek审校合计82,594 Token，其中推理Token已包含在输出Token内，不重复累加。方法用例的重排另外报告2,937输入Token、0输出Token。金额未知。三道原题并行验证，表中耗时不能直接相加为批次墙钟耗时。

## 配置、回退与部署

新增`RAG_CORRECTIVE_REVIEW_ENABLED`，代码及模板默认false，要求同时启用证据审校和重排。本机 `.env.literature`、`.env.aliyun`启用true，原模型、索引、首次查询改写和重排方式保持不变。私有配置修改前单独备份到`.rag-data/config-backups`。

关闭该开关即可回到原一次审校；关闭`RAG_EVIDENCE_REVIEW_ENABLED`前应同时关闭它。已封存的旧评测运行环境不改动。

本次只更新本地代码、构建和本地配置；GitHub同步不等于服务器部署。服务器私有配置、服务进程和索引未更改。

## 验收与下一步

相关自动化测试共256项通过，覆盖：直接修订不补查、无新来源不执行第二次、两次审校和一次补查上限、失败保留回答、剩余时间、跨文献过滤、重复来源、预算保护、稀疏引用、旧图片缓存及备份、最终新增引用与问答历史存储。前端构建通过，并通过ego-browser在独立本地测试服务验证三个状态、未解决项展开和切换历史记录；测试服务不写入真实历史库，验证后已停止。

本次不能宣称整体评分提高。第14题语义判断与第32题主动补查触发仍有不足，下一步应在同一套32份冻结初始输入上做完整对照，既统计现有质量维度，也记录不必要补查、缺口解决、错误修改、调用次数、耗时和费用。正式评测前不要把本次“流程完成”状态当作质量标签。随后增加未用于调试的题目验证泛化。
