# 测量口径与推断边界：条件审校

新增可选`v2_measurement`，最终协议为`bounded-corrective-review-v2.8.1-measurement`，继承v2_causal及其编号修复。仅增加条件测量核查，默认仍为v1，未部署服务器。

程序按问题中的测量与解释词、回答中相对量与绝对量表达、所引用证据中的相对量线索进行启发式路由。触发不代表判定错误；模型需要判断实际测量口径及是否存在必要的推断限制。关键词规则可能漏掉隐含含义，也可能把已有正确限定再次送去检查。

触发后在原审校请求中加入简短指引，复用requirements台账的R80记录实际测量量、回答推断量及必要解释边界。R80缺失或名称改变时诊断不完整，不默认通过。程序只能核查记录存在、编号、引用与修改绑定，不能证明模型真的识别了所有边界。

对于FTIR相对峰面积，要求区分归一化比例与绝对数量/浓度；必要时最小修改已有口径句。不能编造包含限定语的原文引句，也不能把方法解释说成作者直接报告的结论。已有证据足够时不额外检索；有明确校准的绝对量应保留，数值查表与仪器查询不应机械追加限定。条件、引用预算、模型、32768输出上限和两轮审校上限不变。

## 验证方案

第18、32题各3次独立审校，使用`pfi-answer-deepseek-20261102/results`同一冻结草稿与文献库；第5题一次仪器查询对照。另用明确标注的合成材料检查纯数值查询与校准绝对浓度，不算入32题评测。未向模型提供评测标准或旧评分，未调用Jev。

原始记录保存在`.rag-data/evaluations/measurement-20261104`，各次独立目录，不覆盖失败或挑选最好结果。没有本轮32题总分，也不能将历史其他版本结果当成同期对照。

## 首版失败与收紧条件

首版v2.8：第18题第1次请求约181秒失败（review_request_failed，HTTP状态和Token未知），后两次流程completed但答案没有变化，仍漏掉绝对量限制。两次R80都将“回答只称相对量，没有误称绝对量”当成完整回答；限制只出现在内部reason里。这是明确漏检，不能把completed当作修复成功。

第32题首版第1次同样请求失败，另两次补入摘要、保留相关不等于直接换算，但均未在最终回答补齐相对峰面积与绝对数量之别。第5题没有触发核查，答案不变。合成数值和校准绝对浓度对照均保持原答案。

随后仅收紧条件指引为v2.8.1：用户要求解释测量/含量口径或定量换算、且实际量为归一化比例时，最终答案必须明示相关推断边界。内部reason不能替代答案；covered应引用实际回答中的边界句，缺失则最小修改。已有正确限定保留，查数值与真正绝对量不机械增加限定。另将触发日志提前至请求前，使请求失败时也可追溯。没有扩大输出、检索或调用预算。
