# 候选证据重排：实现与实验范围

2026-10-30。固定内容组织85块版，在向量候选筛选与前8个主命中之间增加可开关的重排。原PDF、切块、Embedding向量、表格行检索、关联补全、回答模型及提示词不变。

## 流程

用户问题去除首尾空白 → BGE-M3生成一个查询向量 → 原有Chroma与表格行向量融合形成最多50个父块候选 → 原向量分数≥0.35过滤、去重、跳过孤立向量 → 重排 → 前8个主命中 → 原邻块与表格关联补全 → 原DeepSeek回答和引用校验。

重排使用当前Embedding同一硅基流动服务的`BAAI/bge-reranker-v2-m3`，显式配置凭据，独立实验配置保存在已忽略的`.rag-data/configs`中。网站配置及默认索引未切换。默认`RAG_RERANK_ENABLED=false`；开启时必须同时配置服务地址、模型和密钥。

- 重排收到原问题与每个候选的完整原块文本（含已有章节标签、表题和原表HTML），不注入标准答案，不改写query，不新增类型过滤，不改写表格。
- 一次请求返回所有候选的分数，严格校验数量、索引、去重和有限的0—1分值；按重排分数降序排列，同分保持原向量顺序。
- 向量分数仍保存在`Evidence.score`；重排分数和前后名次另外记录。0.35只用于向量预筛选，不用于重排，不把分数解释为答案正确概率。
- 原单条8000/总24000字符证据预算和补全规则不变。回答模型收到完整原证据及其来源位置，重排不生成新的回答证据。
- 应用不截断候选文本。服务端长文本分段参数显式设为`max_chunks_per_doc=1024`、`overlap_tokens=80`；该过程只用于服务端计算重排分数，不修改本地检索切块。服务内部具体实现不可独立验证。
- 超时60秒，不自动重试、不悄悄退回纯向量排序。失败通过原有错误流程返回，并记录一次调用、响应指纹、状态、耗时及已知用量；未知费用保留未知。

模型原理及请求参数依据：[BAAI模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)、[硅基流动重排API](https://docs.siliconflow.cn/docs/api/rerank-post)。

## 首次排序探测

使用上一轮已封存的第11题候选池，读取其原问题和完整候选源块，仅调用重排，不读取参考答案、不重新调用Embedding、不生成回答。

关键Table 1原候选名次15，首次探测重排为3，进入前8；其重排分数约0.174，仍被保留，说明没有错误套用原0.35阈值。该表含4000转时CI-XI=70.42、8000转时72.54等原数据，但本轮程序未以这些答案数值编写排序规则。

探测1次请求、API报告输入12,627 Token、输出0 Token，耗时1.319秒，货币费用未知。探测与随后正式32题运行分别记账；不使用探测结果替换正式运行输出。

## 验证与后续评测

80项重排、检索、上下文、表格关联及历史接口测试通过，涵盖关闭开关时的原行为、向量阈值与重排分数分离、完整原文发送、乱序索引映射、错误分数和重复索引拒绝、失败无隐式重试、凭据脱敏和费用未知。

正式评测继续使用原32题，每题独立请求；只给本轮新回答新增Jev评分，规则与参考答案保持原样。主对照为内容组织85块版，旧评分直接复用；缺失或内部矛盾不记零分，只比较共同有效题。先核对实际排名及最终上下文，再查看五项问答评分和代价，不凭一次排序探测宣称整体提升。

源文件：

- `backend/literature_rag/application/rerank.py`：父块排序与前后排名诊断。
- `backend/literature_rag/adapters/providers/rerank.py`：API、返回校验、脱敏与用量。
- `backend/literature_rag/application/retrieve.py`：原筛选后的重排接线。
- `backend/literature_worker.py`：开关、请求记录和原错误流程。
- `scripts/probe_qa_rerank.py`：已有候选池的独立排序探测。
- `backend/tests/test_rerank.py`：重排契约及检索行为测试。
