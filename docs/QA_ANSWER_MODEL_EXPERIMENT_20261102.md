# 回答模型对照：GPT-6 Astra 与 DeepSeek Flash

本轮按用户要求测试 GPT-6 Astra，保留当前 MinerU、千问多模态 Embedding、原图输入、查询改写、重排及小节补全。服务端模型目录已确认 `gpt-6-astra`；不使用用户粘贴配置中的另一个型号 `gpt-5.5`。两侧推理档位均为 high；不同厂商的 high 不表示相等计算量。

## 固定条件

- 同一份原始 PDF、同一套 32 道 core_text 题，逐题独立进程，无前题上下文。
- 先以当前含原图的 MinerU＋Qwen3-VL 库检索，复用已冻结的原问题／改写查询。然后让两个回答模型使用完全相同的最终证据文本、顺序、引用编号和原图字节。
- DeepSeek 对照只回放源材料，不读取 GPT 答案、参考答案或评分。回放文件独立封存并记录摘要；不重复支付 Embedding、重排和查询改写调用。
- 查询改写独立使用原有 DeepSeek 配置，更换回答模型不会改变查询模型或向其他厂商发送其密钥。
- 保留每题最多两次生成及原有引用校验；不启用完整性指引，不添加针对题目的提示。
- GPT 使用 Responses API、结构化输出、`store=false`；DeepSeek 使用原有 Chat Completions JSON 输出。接口协议不同，但业务提示、证据和引用校验规则相同；这些适配差异属于本轮模型替换的实际效果。

## 评分和复核

外部评分仅使用 Jev，沿用 `qa-system-five-v1`：必答要点、事实支持、单条引用、引用组覆盖、回答边界。无加权总分。原始评分首个有效结果保留，协议无效／请求失败最多三次，全部尝试保留；失败不计零分。

用户指定最终以 Codex 复核为准。原始 Jev 评分不会覆盖，复核另存：检查参考答案、真实回答、实际引用原文及论文证据；对无法评分的条目补齐，发现过严或过宽之处逐项记录原值、最终值、理由与依据。复核是 Codex 审阅，不称为人工专家金标准。两组均适用相同规则，不能只纠正 GPT 一侧。

原图在本轮回答时真实提供。Jev 当前仍接收原有文字评分包，不直接读取图片像素；若出现仅能由图片判断的陈述，由 Codex 查看相应原图后复核，不能将 Jev 的文字判断冒充图像审核。

## 最终结果

两侧均完成32题。32组最终证据完整相同，且逐次成功生成记录中的实际交付原图编号、位置和哈希均一致。GPT 31题成功、1题校验后拒答；DeepSeek 32题成功。所有回答均使用独立上下文，原问题和改写词复用相同封存结果。

Jev原始有效评分：GPT 31题，DeepSeek 29题。GPT第15题及DeepSeek第15、26、27题各三次评分均出现引用组与单条引用决策矛盾，因此没有有效分；由Codex另行完整补评。原始无效结果保留，不当作零分，不用其分数替代正式评分。

**两种评分口径明确区分：**Jev原始分沿用不变的文字引用协议；Codex最终分还核对该引用号下实际送给回答模型的原图，不能借用当时未交付的图片。该图文证据单位扩展同时用于两个模型，其余要点0/0.5/1、事实支持和边界准则保持原样。因此原始→最终的变化既包括评分修正、补评，也包括图像证据检查，不应全部解释为Jev的语义评分错误。事实和引用指标以各自回答的陈述/引用为单位，两模型的陈述粒度与分母不同。

主要复核例子：

- GPT第10题回答端点及趋势正确，撤销无依据的边界扣分；第11题给出初末数值和非单调反例，已语义表达总体下降，P1由0.5改为1。
- GPT第26、30题和DeepSeek第18题的图形陈述，在实际附加原图上有直接支持，不能只凭文字片段不含这些信息就判为证据不足。第15、26、27题的补评也核对了实际原图。
- DeepSeek第13题的Table 1直接证明波动趋势；第6题公式与质量定义分别贡献必要输入；不能要求每条引用单独证明整句。
- DeepSeek第16题把“不能必然推出纤维变强”说成“不是直接来自单根纤维强度提高”，排除了论文未排除的贡献，P3从1改为0.5，事实支持与边界同时标为部分达标。
- DeepSeek第31题把相对峰面积组分变化说成“氢键总量”变化，并把可能原因确定化，下调对应事实、引用组及边界。GPT第31题同样因额外确定性下调边界。
- 纯资料可用性声明按scope核验，引用分不适用；原始标签中出现unsupported时，不会把它错误算进科学事实引用的分母。

## 如何解释结果

本轮按平台实际交付效果，DeepSeek更稳：成功32/32、要点分与引用表现更好。GPT没有在这套题上形成明确的整体优势。

第7题GPT草稿两次都给出了正确的CI-XI公式，但使用 `[(I200−Iam)/I200]` 作为数学括号，触发现有程序“含数字的方括号即疑似引用”规则，最终统一拒答。本轮未改规则、未替换草稿评分。这个0分归因于**平台引用校验误伤**，不能说成模型不会公式。

只看两侧共同成功返回的31题，最终要点均分为GPT **97.31%**、DeepSeek **96.77%**；GPT只高0.54个百分点。此为诊断子集，不能用它替换全部32题主结果。即使该子集GPT要点略高，DeepSeek的引用及全部维度达标题数仍占优。每种模型只运行一次，不能据此断言普遍优劣或稳定性。

剩余必答扣分：

- 两侧第4题未明确说明不同作用力条件；第15题压力解释语气过强；第18题未明确相对峰面积比例不等于绝对氢键数；第32题未标出摘要0.888与正文0.912冲突。
- DeepSeek另有第16题的过强排除；GPT另有第7题系统拦截。
- 第32题的摘要数值不在两侧共同的最终证据里。换回答模型没有解决这一检索/上下文缺口，不能要求模型凭空补出0.888。

建议先修正公式括号的引用校验误判，再针对实际附图扩展评委输入；之后再考虑是否替换网站默认回答模型。本次没有修改本地或服务器网站的默认回答配置，仍为DeepSeek。

## 调用及费用

- GPT共40次应用层生成尝试，其中38次返回型号为`gpt-6-astra`，2次无有效返回型号/用量；已知用量503,344 Token，另2次用量未知，不能把已知量称为完整总量。

- Jev对GPT共34次请求，报告费用$0.098674338；对DeepSeek共38次请求，$0.120674106；合计**72次、$0.219348444**，包含协议无效的尝试。Codex离线复核未额外调用评分API。

- GPT侧执行了检索，DeepSeek侧回放最终材料以控制变量，因此不把两侧端到端耗时直接作公平速度对比。
