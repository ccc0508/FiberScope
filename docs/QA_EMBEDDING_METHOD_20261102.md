# BGE-M3与Qwen3-VL-Embedding控制变量评测

2026-11-02。按用户要求评测新Embedding模型。本轮只比较同一批文字材料的向量模型替换，关闭图像召回与视觉输入，不把图片效果混入Embedding替换的结论。

## 两组

| 项目 | BGE对照 | Qwen试验 |
| --- | --- | --- |
| Embedding | BAAI/bge-m3，1024维，原兼容接口 | qwen3-vl-embedding，2560维，阿里云原生接口 |
| 文献材料 | 同一PDF、113个原文块、20条表格行、10条关联 | 完全相同 |
| 检索 | 原问题与一条改写分别检索，RRF k=60合并去重后最多50候选 | 相同 |
| 候选阈值 | 每路0.35 | 相同，未做Qwen专项调参 |
| 重排 | 原问题、完整文字候选、原BGE重排模型、最多8主命中 | 相同 |
| 补全 | 原分类、小节、表格关联和正文续句规则；8000/24000字符预算 | 相同 |

| 图像 | 关闭，使用不含图像索引的库 | 关闭，使用Qwen纯文本库 |

## 固定改写与运行隔离

先对原32题分别生成一次检索改写，仅给改写模型原问题，不提供参考答案、证据金标准或旧回答。逐次保存调用、用量、失败与原始改写；失败不挑选重试，两组一致回退原问题检索。

两组复用同一份封存改写，避免生成两套不同query使结论混入改写随机性。只在评测包装器内替换改写依赖，生产worker与检索、重排、补全、回答代码不改。每次答案的改写诊断明确标记replayed_for_controlled_evaluation、api_calls=0；实际改写费用单列一次，不把回放记成额外付费调用。

每组32次新答题，每题新进程，模型仅接收本题原问题及实际检索证据。包装器按原问题哈希读取对应检索改写，缓存没有参考答案或评分内容。题集、原文、块ID/文字/页码/类型/章节/表格行及关联逐项相同；源提交和worker代码相同，仅Embedding身份、向量及相应接口不同。

基线、独立库、私有配置、改写缓存与评测包装器均有指纹。包装器复制进封存的backend并纳入source_files；每题前检查源码和缓存。未知是否已完成的付费请求不自动重放，有效答案不重跑挑选。

两组并行启动，各组按题序执行。端到端耗时不包含已离线生成的改写时间；另外提供改写阶段用量与耗时。此耗时适合两种Embedding路线对照，不能直接与在线每题实时改写的历史耗时比较。

## 评分与统计

同一32道core_text开发题，两组答案均重新生成。Jev沿用原qa-system-five-v1协议与原OpenRouter设置，每份回答独立评分，不接收另一组答案、模型身份或旧分数。

分别报告必答要点、事实支持、单条引用有效、引用组完整、回答边界及五项全达标题数，不算加权总分。只接受首次有效评分，API或格式/一致性失败最多3次，全部尝试计入用量。无效分数不记零，疑点或缺失题在共同有效题对照中排除并披露。

导入时补充兼容生产worker的`refused`状态（旧读取器只接受`answered/abstained/failed`）。保留拒答原文、检索材料及源文件校验和，不重写答案、不换分、不跳过；裁判仍用原五维规则判断拒答是否合适。这是读取状态的兼容修正，不是评分标准调整。

记录两组相同query的候选、主命中、最终原文集合、证据字符预算与首次生成输入是否一致。候选或原文新增数只说明材料变化，不自动解释为必需证据覆盖提高。逐题列出要点和全达标升降，避免将生成随机变化直接归因于Embedding。

用量区分改写准备、问题Embedding、重排、回答及Jev，Qwen图片Token在本轮应为0；不重复相加推理Token，供应商未返回的货币金额记未知。本轮没有新的Luna/DSH调用；旧DSH答案仅为兼容现有导入格式复制，不参与评分。

## 范围

这是同一论文与既有开发题的一轮评测，比较“现有参数下替换Embedding”的效果。BGE和Qwen的维度、供应商与远端实现不同，0.35不是两者等价的相关概率；未校准阈值的结果不能代表各模型最佳能力。远端模型别名与生成/裁判随机性无法完全冻结，不作稳定性或新论文泛化结论。

本轮关闭图片仅用于隔离变量，不修改当前启用图片的MinerU候选配置或网站/服务器配置。图片功能的独立正式评测需要图像题与能核对图片的评分材料，本轮文字评测不覆盖它。
