# MinerU原问题与查询改写：双路检索对照

2026-11-02。按用户要求，在MinerU候选版增加可关闭的查询改写；网站默认配置和服务器不切换。

## 改动

复用原DeepSeek模型、地址和私有密钥。每次提问先发起一次独立、无历史的改写调用，关闭思考，temperature=0，最多768输出Token，超时30秒，不重试。要求只返回一条JSON检索句，保留材料、数字、标识符、单位、比较、否定、不确定性和全部子问题，不预先生成答案或认定机制。程序拒绝空白、超1200字符、错误结构及丢失数字/技术标识符的结果。语义是否完整无法只靠程序保证，是本轮评测内容。

改写失败时记录状态并只检索原问题；完全相同的改写也只检索一次。后续Embedding、向量库或重排失败仍沿用原错误处理，不伪装成成功。

原问题和有效改写分别使用原BGE-M3模型生成向量，各取最多50个父块（包括原表格行召回），各自按0.35阈值过滤。每路按向量分数排名并去重，然后按照块ID合并。块ID在当前元数据库中全局唯一并关联文献，因此不会把不同论文的相似文字误删。同表的多条行表示仍先映射到同一完整表格父块。

双路合并采用等权RRF（k=60），每路每块仅贡献一次1/(60+rank)。不直接比较两条不同query的余弦分数；并列时依次用原问题排名、改写排名和块ID确定顺序。排除缺失原文的向量后，最多保留50个不同候选，再用**原问题**进行原BGE重排，最多选8个主命中。公共块的Evidence.score保留原问题余弦；改写独有块保留该路余弦，RRF与重排分数另存。

候选预算是固定50个；这意味着改写可能引入新证据，也可能挤掉原问题候选，不能声称两路一定比单路完整。正文/表格/公式可靠小节补全、明确表号关联、续句兜底和8000/24000字符预算均不变。原问题与改写句不会作为回答证据；生成器只回答原问题，仍使用原High思考设置和原提示词，回答指引关闭。

诊断记录两条query、每路候选及余弦、表格行来源、重合数、改写独有候选、RRF预算筛除、独有主命中和独有最终原文。重排诊断中的vector_rank在双路时表示融合后输入次序，已明确标注。改写与两次Embedding的请求用量逐次保存；未知费用不记零。

## 评测设计

固定同一代码提交、同一113块索引、20条表格行表示、10条正文表格关联、原PDF及32道core_text题。两组使用独立冻结代码和库副本，唯一配置差异为RAG_QUERY_REWRITE_ENABLED。

- 对照：原问题检索，32次新答题。
- 试验：原问题加一条改写，32次新答题。
- 两组每题独立进程，不带历史、旧回答、标准答案或评分；两组并行启动，各组按题序执行。
- Jev沿用原qa-system-five-v1协议与原模型设置，每个新回答独立评分，不看另一组答案或历史分数。
- 必答点、事实支持、单引有效、引用组完整、回答边界五维分别报告；不计算加权总分。缺失分数不记零，参考标准疑点单独披露，比较使用共同有效题。
- 只接受首次有效评分，失败评分请求最多3次且全部计费记录；有效回答和评分不重跑挑选。
- 分别统计改写、问题Embedding、重排、生成和Jev用量，推理Token不重复相加。检查每路重复、候选增减与最终证据变化；新增候选数本身不代表必需证据覆盖提高。

此次是单篇论文、已有开发题的一轮同期对照，不能证明新论文泛化或稳定性。远端模型别名和生成随机性无法冻结；即使同期对照，也不能把单题回答变化完全归因于候选变化。

## 配置与保存

`RAG_QUERY_REWRITE_ENABLED`默认false；开启要求现有重排和DeepSeek已配置。示例在backend/.env.literature.example，私有配置在已忽略的.rag-data/configs。

本轮私有运行目录为.rag-data/evaluations/pfi-query-original-20261102-r1和pfi-query-rewrite-20261102-r1，评分与探测记录在.rag-data/evaluations/query-rewrite-20261102。正式评测从UTF-8题目文件读取问题。首次手工接口探测遇到PowerShell管道中文编码损坏，已保留该请求，排除答题评测并单列其用量。
