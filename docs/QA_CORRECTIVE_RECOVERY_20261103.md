# 有限纠正 v2.1：审校阻断修复

2026-11-03。修复对象是实验版 `RAG_CORRECTIVE_REVIEW_VERSION=v2`，运行记录版本更新为 `bounded-corrective-review-v2.1`。默认仍为 v1；没有改变服务器配置。

## 修复内容

1. **允许同一陈述核对多个来源。** 原先只要重复使用同一个陈述编号就拒绝整轮；现在按“陈述编号、来源编号、原文引句”区分检查。摘要和正文可以分别核对，同一来源的不同原文片段也可以核对。完全重复的记录仍标记为诊断错误。
2. **将辅助诊断与实际修订分开验证。** `requirements` 和 `claim_checks` 的格式、位置、引句错误逐项记录；不再丢掉其余通过检查的修订。实际修订仍逐项检查原始编辑位置、真实引句/图片、已提供的引用以及合并后的引用格式。错误的修订依据仍被拒绝，不自动补造原文或数值。
3. **只执行合法补查。** 无效来源、重复需求编号、越界位置和第二轮继续补查等要求降为未解决，不交给读取器。有效的其他补查仍可执行，最多两次动作、两次审校请求及原有时间/上下文预算不变。
4. **程序数值补查独立触发。** 符合数值核实规则且当前缺少摘要/结果区域时，即使第一次模型响应失败或诊断不完整，也可在剩余预算内补查。此规则仍不读取标准答案，不预设正确数值。
5. **准确继承已执行的修订。** 第一轮接受的编辑记录为已执行；第二轮失败时不会再按第二轮的编辑编号误判第一轮修订未执行。替换、删除和追加后的陈述位置重新映射，旧编辑编号不传作下一轮待执行编辑。

无效诊断会保留 `diagnosis_errors`，实际修订保留 `accepted_issue_indexes`、`rejected_issues` 和来源依据。只要最终诊断不完整，页面状态仍是“审校未完整完成”，不会因为保住了部分修订就显示全部审校成功。格式检查不保证科学语义正确。

严格边界仍保留：无法解析的JSON、非法顶层字段以及实际修订列表本身的格式错误不会被自动猜测修复。对合法JSON中辅助诊断的逐项恢复，不等于接受任意模型输出。

## 验证口径

192项相关测试通过，覆盖同一陈述多来源、局部诊断格式/引句/位置失败、修订依据仍需真实来源、非法补查不执行、首轮请求失败后程序补查、第二轮不递归，以及第一轮已执行编辑的状态继承。

真实模型只验证第14、23、24、32题，每题一次。使用上轮相同原始草稿、初始证据及图像，独立上下文，最多两次DeepSeek审校；没有重新生成首次回答，没有调用Jev或Luna，也没有更新32题总分。结果及来源核对见[四题修复验证](../data/literature/qa-evaluation/reports/corrective-v21-fix-20261103/comparison.html)。

本地原始运行目录：`.rag-data/evaluations/corrective-v21-fix-20261103`。报告保留修复前后回答、状态、来源核对和完整诊断；上轮32题报告保持原样。四道定点回归题不能证明全量质量或稳定性。
