# MinerU上下文补全：固定主命中的对照方案

2026-10-31。比较同页前后相邻块和按小节补全，先做离线实验，不接入网站默认检索流程。

两臂复用原MinerU章节107块索引，以及32题答题记录中封存的前8个主命中。没有重新解析、重新切块、重新检索或重排；生成时不提供参考答案、历史答案、评分或评测证据标注。两臂均新生成一份答案，并独立使用原Jev评分协议，每题接受首个有效结果，最多3次评分尝试。

## 固定条件

- 同一篇14页论文、同一107块索引、相同32题、相同主命中内容、顺序与分数。
- 使用原107块答题时封存的后端代码、DeepSeek模型别名及High设置，提示词、输出结构和最多两次格式/引用纠正不变。未启用后续重排、表格行检索或回答指引。
- 两臂均限制每条证据8000字符、全部证据24000字符；不得截断表格或丢弃主命中。
- 同一题的两臂使用独立工作进程并发执行，下一题交换提交顺序；单进程最长300秒。
- 旧版邻块补全在准备阶段必须逐字段复现历史32题的完整上下文，否则停止实验。

## 小节补全规则

1. 只接受原结构映射中章节节点及归属均为`inferred`的候选，参考文献不作为普通研究小节扩展。这个标记只表示程序规则推断成功，不等于已由人工确认。
2. 以当前块所属的最细现有小节为候选范围，允许跨页。不会自动把整个父章节放入上下文，也不会扩大到同父章节的其他小节。
3. 同一小节的多个主命中合组；所有主命中先预留完整空间。分组过长时拆为多个证据，预算不足明确报错，不能静默舍弃主命中。
4. 正文显式引用`Table N`时，可关联同一论文中带相同表号的完整表格；主命中是表格时，优先关联同小节中提到该表号的解释正文。补充材料表号`S1`不等于正文表号`1`。
5. 其余候选按与主命中的原文块距离排序，在预算内逐块补充。短小节可能完整纳入，长小节只纳入部分候选；这一步没有用新模型判断语义相关性，因此不将候选称为已确认的关键证据。
6. 已分配的原块不重复加入其他证据，输出保留原块编号、页码和原文。原文不连续时保留明确标记。
7. 章节归属缺失或不确定时回退到原同页邻块范围；未改变原始正文或表格数据。

新增实现位于`backend/literature_rag/application/section_context.py`，默认检索器未调用它。该方案需要调用方提供经校验的原文块与章节映射。

## 观察与评分

先记录补入/跳过的原块、跨页范围、最终字符数及预算状态，再分别比较原五项评分和联合达标情况。新增证据数量、跨页数量只作为诊断，不能当成正确率。陈述数与引用数可能变化，事实及引用率同时保留分子和分母。无效评分保留缺失，不记零；报告包含全部32题。

第11题表格和第32题摘要可用于事后定位问题，但程序不能读取这些题的标准答案或为指定题添加规则。跨小节矛盾证据未必能靠本轮补全找齐。单次结果不证明稳定性或因果归因，应结合实际输入和生成内容解释。

## 运行与封存

控制程序`python scripts/section_context_20261031.py`依次执行`prepare`、`run`、`grade-prepare`、`grade`、`collect`、`report`。私有输入、密钥配置、尝试日志和原始结果保存在已忽略的`.rag-data/evaluations/section-context-20261031`；公开报告位于`data/literature/qa-evaluation/reports/section-context-20261031`。

准备后封存生成代码、补全规则、问题、每题主命中、各臂完整上下文及默认配置的SHA-256。已完成结果可续跑但不能覆盖；中断的付费请求需先检查，不能自动重放。报告程序只计算原始Jev标签，不重新评分或修改原分。

用量同时记录回答Token、Jev请求及API报告费用。没有调用Embedding和重排不等于回答免费；回答实际货币费用无法从Token总数直接确定，保持未知。
