## 12题为什么失败

失败题：**13、15、16、20、24、25、26、27、28、29、30、31**。

它们均在初答生成之前触发 `OverflowError`。这些题的工具结果JSON本身已达162690～260537字符（尚未算消息包装和其余内容），超过160000字符上限。因此可以确认是文本上下文预算，不是图片字节上限。

具体链路：

1. `search_literature` 返回自动补全证据，同时带原始 `source_chunks`、位置和其他元数据。
2. 原生工具适配器将整个结果序列化后加入消息历史；同一证据正文和原始块可能重复占用篇幅，多次不同查询也可能返回重叠证据。
3. 循环只在下一次模型调用前检查总字符数；超限时直接抛错。
4. 此时没有初答，也没有可用的压缩/提前收尾分支，最终空答案。

本轮模型调用最多5次、工具请求最多6次、单题最长117.177秒，尚未耗尽6次/8次/240秒限额。不能据此认为这些上限已足够或最佳，因为上下文限制提前截断了探索。

## 成功答案仍有什么问题

- 第4题必答63/57 °SR及不同作用力齐全，但额外把非线性关系直接解释成“不能内插”，限制说得过强。
- 第14题机制链正确，额外估读Figure2把WRV末端读得偏高。原图软木约190%、硬木约180%，不是两类都到200%以上。
- 第17题正确说软木湿纸幅增幅更大，但用“零距强度未降低”排除本征强度变化，证据不足。
- 第22题跨表数值正确，额外声称不是同批数据、明确以五点计算相关和确定性氢键形成解释，超出原文。
- 第32题纠正相关对象、指出摘要/正文冲突并拒绝直接换算，但把浆类写成“同一树种”。

还有一些段落没有就近引文，或者所附引用只覆盖复合段落的一部分。自由格式答案平均1216.8字符，复核常增加方法与限制段落；补充越多，额外陈述的事实与引用负担也越多。

## 与上一固定流程怎么比较

上一轮关闭程序内容校验的固定流程端到端要点为99.48%；本轮62.50%，下降36.98个百分点，主要来自12题无法交付。成功20题的要点100%不能证明Agent比固定流程更强，因为拒答、纠错等题在失败子集中较多。

本轮是自由格式答案，按原文段落、列表、表格组织核查，并保留显式前置/后置引用范围；旧版是结构化陈述。事实与引用分母不完全一致，不能把这些比例差直接当作严格消融结论。Jev只收到文字及图像元数据，Codex另行核对实际原图。

题集是反复使用的单篇论文开发题，本轮仅一次；不能据此确定泛化能力、稳定性或最佳预算。

运行后文件摘要检查确认原文元数据库及图片等非Chroma文件未变，但Chroma的`chroma.sqlite3`、`data_level0.bin`、`length.bin`发生变化。工具路径没有显式重新入库/upsert，现有集合仍为2560维、113条；变化与查询期间的持久化写回一致，但没有运行前逻辑向量摘要，不能证明索引逐字节或逻辑内容严格相同。该限制已记录在`library-audit.json`和报告统计中；后续应另复制文库并预采逻辑向量摘要。

## 建议的下一步

先修上下文管理，暂不迁移更复杂的结构化审校：
