## 与原评测的关系

- 原始回答、v1历史报告、v2受控注入的历史Codex初评保留原样，不改写、不冒充独立评分。
- 当前适配器只接受带完整指纹的**v2运行目录**。v1的30题不能直接用这套规则重命名重评；应先生成对应v2原版回答，或另做保持v1规则的适配器。
- v2题集的原始`rubric.json`仍记载编制时的人工来源评阅模式。当前独立运行契约为`qa-independent-judge-v2`：沿用其分值/必答/引用等规则，使用独立API评分，不修改已冻结材料或题集指纹；旧版工具和失败记录单独保留。
- 文本、受控注入、图像边界按组汇总；不合并总体分数。已完成的32题文本结果见完整报告，不能用两条注入任务代表全文献问答质量。

## 评分模型看见什么

题目、预期作答行为、参考答案和评分要点、原文证据及带指纹的完整论文文本；同时提供当时的完整回答、claims、实际引用与全部检索片段。
不会提供回答模型名称、耗时、历史评分、历史评阅理由。参考证据和实际检索结果明确分开，不能把标准答案中的内容误认为系统检索到了。
模型逐点给出0/0.5/1、边界判断、逐条事实支持、引用配对、检索诊断、关键错误及中文理由。裁判发现参考答案疑点时单列，暂停生成汇总，等待标准核查。
没有向裁判开放工具；论文/回答/检索片段均视为待审数据，片段中的提示注入不能作为评分指令。

程序只做结构、身份、指纹、引用原句及分值范围校验，再计算均分和达标率；**程序不会补写语义分数或修正模型意见**。
`reference_evidence`/`paper_text`支持事实真伪核查；引用是否支持仍只根据回答当时被引的实际片段，不能用标准证据替代。

## 私有配置与运行

模板：[backend/.env.judge.example](../backend/.env.judge.example)。实际文件`backend/.env.judge`被Git忽略，密钥与回答模型配置分开。

```dotenv
QA_JUDGE_BASE_URL=https://yostoken.top/v1
QA_JUDGE_MODEL=gpt-6.1-sol
QA_JUDGE_API_KEY=在私有文件填写
QA_JUDGE_API=responses
QA_JUDGE_TIMEOUT_SECONDS=180
QA_JUDGE_MAX_OUTPUT_TOKENS=16000
```

支持显式选择`responses`或`chat_completions`；不会暗中切模型、换接口或反复重试。默认一次最多新增1次付费请求。
以下示例使用新的独立评分目录；该目录不能在原回答目录里。完整重评需保留相同任务选择与配置。

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/judge_qa_eval.py --run-dir .rag-data/evaluations/pfi-v2-injection-20261025-r1 --output-dir .rag-data/evaluations/independent-judge-new-run --limit 2
```

`--limit`控制本次最多新增调用数，`--task`可重复指定确切任务号。已完成任务复核后跳过；默认不会自动补跑失败或未知中断任务。
如显式选择部分任务，只保存逐题评分，不发布冒充完整基线的汇总。

每个评分目录保存：

| 文件 | 内容 |
| --- | --- |
| `judge-run.json`、`harness/` | 模型/接口、来源指纹、提示词版本、实际工具副本，不含密钥 |
| `tasks/*.json` | 请求指纹、原始成功响应、评分或失败状态、请求ID、耗时、Token |
| `reviews.jsonl` | 全部通过校验的独立模型评分，注明未参与出题 |
| `progress.json` | 已完成/失败/待处理数量，用量，实际账单未知时记null |
| `summary.json` | 仅全部原任务已处理、评分均有效且无参考答案疑点时产生 |

请求前写入pending并锁定评分目录，避免两个进程重复收费。网络超时可能已产生上游用量，保持失败记录，不把它算成答案错误或正确拒答。
更改代码、参数、题目或回答后必须创建新评分目录。未知中断时先确认旧进程结束，再处理锁文件；需要再次调用时显式使用新目录，并保留原失败记录。
JSON结构、原句或缺陷映射不合格时记`invalid_scorecard`；不由开发助手手工填成“正确分数”。
Token不等于实际费用；未取得第三方账单前不估算扣费金额。

### 显式补评、结构校验与分组汇总

- `judge_qa_eval.py --repair-record 原任务JSON --task 题号`仅接受拒收或接口失败的记录，创建新目录并保留原件。只给裁判机器校验失败信息、合法字段及原文短句，不给旧语义分值。
- 默认每题最多一次格式补评；确有需要时显式设置`--max-protocol-repairs 2`或`3`，仍有上限。网络失败默认最多两次显式补试，最后一次额外补试需显式设置`--max-transport-retries 3`；较长等待单独记录，不改变模型或请求内容，最长600秒。超时上游用量不能当0。
- `revalidate_qa_judge.py --run-dir 原回答目录 --record 拒收JSON --output-dir 新目录`不调用模型。只补缺失编号、修正唯一确定的字段关联，或将依据模型已有分值计算出的未关联问题列为程序诊断项；不能改任何分值、理由、原文引句或有歧义的关联。
- `aggregate_qa_judges.py --run-dir 原回答目录 --review-dir 分组目录 ... --output-dir 新目录`只读校验原API响应、输入和源码指纹，然后合并全量评分。有效初评不能被替换；缺题、多个有效评分或标准疑点会阻止发布完整汇总。所有失败及补评的已知用量一并统计。
- 规范化记录在`structure_normalizations`/`computed_issue_links`中，与模型原始输出分开；原文不匹配或检索标签错误仍须由模型重新评阅，程序不能填成“正确”。这些校验不等于领域专家的科学判断。

服务器使用`/opt/fiberscope/venv/bin/python`运行同一工具，并显式传入`--env-file /etc/fiberscope/judge.env`。
这是离线评测配置，不加入网站的服务环境，网页请求不会自动触发裁判调用。现有备份脚本复制整个`/etc/fiberscope`配置目录，因此后续定时备份会包含该文件，备份仍仅root可读。

## 同一回答的裁判重复性

固定已保存回答，另建两轮全新评分目录；每题都是独立system+user请求，`store=false`，不提供先前分数或对话编号。不能用重新生成的回答来代替这项实验，否则会混入RAG生成波动。
相同模型、提示词、评分标准和初始请求指纹需要冻结为研究契约。有效评分不补跑；机器校验失败与网络失败保留原记录并显式恢复。纯初评数值与失败恢复后的正式评分分开比较。

`compare_qa_judges.py --study-dir 研究契约目录 --run-dir 原回答目录 --review-dir 第一轮汇总 --review-dir 第二轮汇总 --review-dir 第三轮汇总 --output 新比较JSON`只读复核全部原API输出、失败恢复链及指纹，不调用模型。
它计算必答要点一致率、绝对差、二次加权κ、逐题波动、严格达标与关键错误有无翻转，并检查返回响应ID是否复用。缺失初评不能按0分计；有标准疑点或未完成的正式轮次不能发布完整比较。
两轮已执行，分别有效31/32和32/32；第二轮PFI2-026在额外补评后仍未通过引句校验，保留为评分失败。三轮共同31题均分89.78%、90.32%、90.59%，6题严格达标判定变化；详见[稳定性报告](QA_JUDGE_STABILITY_20261026.md)。
默认缺题仍阻止完整比较；显式`--allow-incomplete`只比较三轮共同有效题目，逐轮覆盖、排除项和每两轮可比题数另列，缺失不记0。该模式不绕过原API输出、来源指纹和失败链校验，不能把子集均分称为完整32题得分。这衡量评分器重复性，不等于RAG生成稳定性或专家正确性。

## 限制

独立裁判减少开发者直接打分的偏差，但仍可能误判，题集本身也仍是AI编制的开发集。尚未完成领域专家抽样校准。
这符合[OpenAI官方评测指南](https://developers.openai.com/api/docs/guides/evaluation-best-practices)中采用明确评分标准、记录结果并以人工反馈校准自动评分的做法。
这里的调用使用用户指定的第三方服务，其可用性、功能与价格不能由OpenAI官方文档保证。
