# 仓库内容管理

代码仓库保留运行、建库、测试、排错和部署所需资料。个人汇报和生成产物保存在仓库外。

| 内容 | 存放方式与原因 |
| --- | --- |
| 前后端源码、数据库迁移、导入器、依赖锁、部署模板 | 保留在Git，支持重建和维护 |
| README、接口契约、操作说明、数据口径和测试方法 | 保留在Git，描述当前实现 |
| 原始实验Excel、字段解释、评测题集、已封存的回归证据 | 保留在Git，是建库、来源追溯和回归核对的依赖；仍属于授权研究资料，并非可任意再分发的数据 |
| 个人汇报PPT、项目分工PDF、旧交接文档、具体服务器迁移记录 | 移至仓库外，包含个人、研究或实际运行环境信息，通用操作说明已在仓库中保留 |
| 生成的Word、Excel、PDF、截图及独立作答材料包 | 移至仓库外，`output/`整体忽略，避免重复收录研究内容和现场信息 |
| 重复ZIP、根目录旧界面草稿和已合并补丁、人工标注交付包 | 移至仓库外；正在使用的Vue设计预览源码保留在工作区 |
| 密钥、真实环境文件、数据库备份、问答记录和运行时文献索引 | 保持本地私有并忽略；应用依赖的运行时目录不能随意移动 |

2026-10-31的整理采用可恢复移动，并在仓库外保存原路径、Git跟踪状态、大小及SHA-256清单，逐文件校验归档一致性。恢复时按清单复制回原相对路径；私有资料不要重新加入Git。

新增开发说明使用相对路径或通用占位路径。提交前检查暂存区，避免将姓名、联系方式、真实服务器地址、账户凭证、原始研究图像或完整交付包夹带进来。`.gitignore`只能防止未来误加，不能清除既有Git历史。

本次移出只清理当前版本；旧提交中的文件仍可能被访问。清除历史需要另行安排历史重写及所有克隆副本的同步；若发现真实凭证，需先撤销或轮换凭证。
