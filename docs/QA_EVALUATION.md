## 题集字段

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定题号，例如PFI-024；修改题意需更新版本 |
| `category` / `difficulty` | 题型与编写时估计难度，不是实测难度 |
| `question` | 唯一发送给待测系统的用户问题 |
| `expected_behavior` | `answer`、`flag_conflict`、`partial`或`abstain`；是评测标签，不要求回答中输出这个字符串 |
| `reference_answer` | 按原文整理的参考回答，允许语义等价表达，不作逐字匹配 |
| `key_points` | 必须覆盖的要点；每题内有独立P1、P2等编号 |
| `evidence_ids` | 原文目录中的证据编号；不是回答系统应输出的引用编号 |
| `evidence_requirement` | `all`表示要组合这些依据；`any`表示任选一个等价依据即可 |
| `kind` | `direct`直接报告、`derived`计算、`bounded_inference`有边界的整合、`scope_limit`全文范围判断、`corpus_scope`文献清单判断 |
| `numeric_checks` | 数值、语义标签、单位和绝对容差；辅助复核，不能凭数字出现就自动判正确 |
| `critical_errors` | 本题关键错误；触发任一项都不能算严格达标 |
| `absence_reason` | 拒答/部分可答的缺失依据，说明检查了什么范围 |
| `grading_notes` | 特殊口径、可接受替代说法及边界 |

证据目录的`baseline_chunk_id`只对应冻结的44个片段。未来重新切块时应按文献内容指纹、PDF页码和原文重新匹配，不能继续机械要求命中旧ID。
原文摘录统一了Unicode兼容字符及空白，保留语义；表格要连同标题、浆种、行列标签核对，不能只看一串数字。
`verification`是编写时的来源核对记录；离线程序只能复查指纹与位置，不会自动证明语义正确。

## 评分方法

先保存系统实际输出，再在评分模板的副本上评分。参考答案、`expected_behavior`、原文摘录和评分要点**不能送给待测回答系统**，否则评测泄漏答案。
本版采用按原文和具体要点评分，不使用回答模型给自己打分，也不把相似度阈值0.35当成正确概率。

### 1. 答案要点与证据边界

每个要点给0、0.5或1分：

- 1：语义正确，条件、单位和必要限定完整。
- 0.5：方向基本正确，但缺少实质条件、单位、计算步骤或限定；该要点不能同时出现矛盾结论。
- 0：缺失、错误、与原文冲突或无依据猜测。

一题的要点得分为各要点均值；总体先算每题均值再取平均，避免要点多的题天然权重更高。
同时按题型报告分数及分子/分母。未评分不能当0分，未完成评分时只能报告已评覆盖范围，不能称为完整基线。

另外给证据边界判断0、1、2分：

- 2：符合预期行为；有证据就回答、冲突就指出、部分可答就拆分、确实缺证据就说明不足。
- 1：部分正确，但可答部分遗漏或边界没有说明清楚。
- 0：编造缺失数据、可答题整体无依据拒答，或掩盖题目已问及的原文冲突。

数值题必须同时核对指标、浆种、转数、单位和数值角色。正确换算可接受，例如3.33 N/mm可换算3330 N/m。
3.41个百分点与4.66%的相对降幅不能互换；图上的估读值不能冒充逐次实验原始值。
模型在参考答案之外补充了内容，也必须核对；漏掉参考答案之外的错误会高估质量。

### 2. 原文支持程度

将回答拆成可核对的实质事实陈述，逐条标注：完全支持1、部分支持0.5、无支持0、与原文矛盾0。
原文支持率为这些分值之和除以被评陈述数，同时报告各类数量。由表格计算得到的结论需有正确输入和运算。
作者使用“可能”的解释，被改写成唯一确定机制，不能判完全支持。

纯拒答、能力说明等没有适用事实陈述时，分母为0，记`null / 不适用`，不能直接记100%。
“资料不存在”的判断结合完整正文审阅和文献清单；上下文片段只是定位线索，不能单独证明全文缺失。

### 3. 引用准确性与覆盖率

- 引用准确率：支持对应陈述且文献/页码正确的“陈述—引用”配对数 ÷ 全部配对数。
- 引用覆盖率：至少有一条正确引用的应引用事实陈述数 ÷ 全部应引用事实陈述数。

多个引用逐对检查；编号存在、页码合法都不足以判为支持。一次引用不能为同段所有未支持内容兜底。
含需引用事实但完全没给引用时，准确率因无配对记`null`，覆盖率为0；若一个需引用事实也没有，两项均为`null`。
正确说明当前文献库缺第二篇论文不强制伪造一条PDF引用；它应由文献清单支持。

### 4. 检索诊断

针对需要正文证据的要点，检查保存的全部检索片段是否足以支持它，标注`complete / partial / missing`。
证据完整召回率为`complete`要点数 ÷ 适用要点数；按题平均和总体分子/分母分别保留。
`scope_limit`与`corpus_scope`不进入正文检索召回分母，它们依靠范围核查。

旧片段ID命中只能作定位信号。若系统找到了另一处同等证据，应经原文核对后认可，不能仅因ID不同扣分。
原文冲突题需要两处冲突依据都到位；只检索摘要不能称为证据完整。
据此区分：证据没有找到、证据只找到一半、证据已找到但回答错误。

### 5. 严格达标率与运行指标

一题严格达标须同时满足：系统完成响应、全部要点1分、边界判断2分、无关键错误、所有被评事实都受支持，并且适用时引用准确率和覆盖率都为100%。
该规则只是本题集的严格诊断标准，不是上线安全保证。总体必须同时列各项分数，不能仅给一个总分。

单独记录：

- 30题的响应完成数、超时数、供应商失败数、正常回答数、拒答数；服务失败不能冒充正确拒答。
- 可答24题的错误拒答率、4道缺证据题的正确拒答率；冲突题和部分可答题另行报告。
- 端到端耗时的中位数及P95，并说明样本数和P95算法，例如最近秩法；超时按超时单列。
- Embedding和每次生成调用的Token、纠正重试次数及已知用量覆盖率。供应商未返回的用量记未知；没有价格依据就不计算费用。
- 首次单次运行只能算初始结果；存在随机性，需要后续重复运行才能说明稳定性。

评分模板中的`claim_assessments`后续填写逐条陈述与支持标签；`citation_assessments`填写陈述ID、实际引用编号及是否支持；
`retrieval_point_assessments`按P编号填写检索支持状态。关键错误列表、评分人、运行编号及依据说明一并保留。
全部字段初始为`null / unreviewed`，不能把空模板当作评分结果。

## 原文中特别需要保留的问题

1. **相关系数冲突**：摘要针叶木0.888，正文3.4节0.912；PFI-024要求明确报告两处来源，不替作者无依据纠错。
2. **峰位约值**：正文约3227 cm⁻¹，Figure 6两类纤维分别标注3226和3228；PFI-020允许清楚说明这个口径。
3. **打浆度疑点**：方法部分把阔叶木0转写为0 °SR，但Figure 2显示非零柱；本版不把该疑点设为唯一数值答案，保留原文，未自行修正。
4. **缺附件与原始数据**：Table S1只有外链，正文未含其数值；Figure 3不包含逐次重复值。不能靠图或常识造出精确原始数据。
5. **有限结论**：现有研究中的相关性和作者机制解释，不等于各因素独立的因果贡献；FT-IR拟合r²也不等于纸张预测模型验证R²。
6. **形态指数口径**：3.1节关于宏观细纤维化指数的文字趋势与Figure 1图示需进一步复核。本版没有把该走势设为唯一标准答案，PFI-016仅考察纤维长度比较及条件限制。

## 离线校验

在项目根目录运行，仅用本地文件，不读取模型密钥，不打开Chroma，也不访问模型API：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/validate_qa_eval.py
.\.venv\Scripts\python.exe -X utf8 scripts/validate_qa_eval.py --baseline .rag-data/baselines/qa-v1-20261024
```

第一条校验公开题集的文件指纹、唯一编号、题型分布、证据引用、单位/容差字段与空评分模板；结果中的`source_check`为`not_requested`。
第二条另外核对冻结manifest、代码版本、PDF及SQLite指纹，使用只读连接逐段检查原文摘录属于对应文献、片段和页码。
它验证来源定位和文件完整性，**不判断参考答案的科学解释是否正确，也不产生问答质量分数**。
完整冻结快照仍可另外使用`freeze_qa_baseline.py verify ... --check-index`验证。

评分时复制模板到`.rag-data/evaluations/某次运行/`，实际回答、评语和结果保存在该忽略目录；公开模板保持空白。
服务器同步材料放在`/opt/fiberscope/evaluations/pfi-qa-eval-v1/`，与在线记录库分开；这一步不改变在线问答逻辑和文献库。

## 运行基线的约束

批量运行和汇总工具已实现；每次运行遵守以下约束：

1. 复制冻结快照到独立运行目录，用冻结代码及匹配的私有模型配置；不能直接写冻结库。
2. 保留当时的检索、提示词、模型、阈值与最多8段证据等配置；运行器仅读取`question`作为用户输入。
3. 每题保存原始回答、全部检索片段、逐条引用、配置、失败原因和实际用量，题号与运行号关联。
4. 按本规则评分，输出逐题问题清单和基线报告。运行实际调用Embedding与回答模型；当前已有一轮结果，不应为了刷新报告重复付费调用。
5. 优化后用同一题集、同一论文范围比较。扩展文献库后另建题集/基线，并让原算法在同一新库重跑，区分算法和语料增量带来的变化。

### 工具与结果保存

`scripts/run_qa_baseline.py prepare`校验题集和完整冻结快照，创建全新的私有目录，复制原版worker、文献和私有模型配置；不会覆盖旧目录。
若Git归档的LF字节与冻结工作区换行不同，`--reference-source`仅在参考文件的原始指纹吻合、且与归档源码除换行外完全相同后，恢复原字节。
参考目录不能换成已经优化过的新代码；本轮服务器隔离运行时保留了可验证的旧源码。

`scripts/run_qa_baseline.py run --run-dir 私有运行目录`逐题调用独立worker，单题90秒，保存`results/`、`attempts/`和`progress.json`。
只将问题和数据路径传入worker，既有结果按题号/问题/运行号和指纹检查后跳过；未知中断题拒绝自动付费重放。网络超时与worker错误记失败，不记正确拒答。
运行前检查原模型、参数、供应商地址指纹和完整源码，清除可覆盖配置的RAG/LITERATURE环境变量；原始错误不直接写入公开输出。

初评结果保存到私有`reviews.jsonl`，每条记录必须覆盖所有要点、返回claim和实际引用配对，并附理由与响应文件指纹。
`scripts/summarize_qa_eval.py`只汇总已明确填写的评分，不靠关键词自动判断科学正确性，也不调用裁判模型。例如：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/summarize_qa_eval.py --run-dir .rag-data/evaluations/qa-baseline-20261025-r1 --reviews .rag-data/evaluations/qa-baseline-20261025-r1/reviews.jsonl --output .rag-data/evaluations/qa-baseline-20261025-r1/summary.json
```

汇总工具要求完整逐题评阅，拒绝把失败调用当成已完成语义评测；如有运行失败，应先按`progress.json`单列故障，不能填上虚构答案分数。
逐条复核以模型返回的claim对象为单位，复合陈述内部有不支持内容不能全给满分；它不是原子事实级评测。
题集`manifest.json`的`quality_run_status=not_run`保留编写阶段状态，属于不可变题集元数据；实际运行状态、初评分数及局限由独立运行记录与报告承载。

题集制定采用目标、数据、具体评分标准及后续持续比较的工作顺序，参考[OpenAI官方评测指南](https://developers.openai.com/api/docs/guides/evaluation-best-practices)。
本项目使用本地文件与评分规则，不依赖OpenAI托管评测服务。
