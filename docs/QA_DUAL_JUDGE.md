# 同一回答的GPT与Jev独立双评

当前采用[统一评分标准v3](QA_SCORING_V3.md)。在同一份已保存回答上，GPT和Jev独立评要点覆盖、事实支持和引用支持；不互相看到评分、理由或之前的对话，不重新生成RAG回答。

## 本轮研究契约

2026-10-26启动`qa-scoring-v3-dual-20261026-r1`，来源为`pfi-v2-core-20261026-r1`的32份原回答。每个裁判先各评一轮，共64次计划初始请求；不是三轮重复性实验。

研究目录在调用前保存源回答及题集指纹、共同规则指纹、两套初始请求指纹、模型公开配置和工具副本。每题均为独立请求，GPT不保存响应为会话上下文；两种裁判均不接收旧分数或另一裁判的结果。

首题接口验证保留为正式初评，成功后仅继续其余31题。失败记录保留，已有效的评分不重跑。结构问题优先尝试零调用复核；只允许机械结构归一化，不能补填或更改语义分数、原文引句。必要补评另存独立目录，仅提供机器校验信息，不给旧语义评分。

本轮GPT额外请求上限16次，每题最多一次协议修复和两次网络失败补试；正常评分和补评分别记录。鉴权、权限或余额错误停止继续补评，不把未知费用当零。

## 独立对照工具

[compare_qa_dual.py](../scripts/compare_qa_dual.py)用于一轮对一轮比较，不需要把一轮结果复制三份。它不调用模型，也不判定某个裁判更正确。

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/compare_qa_dual.py `
  --run-dir .rag-data/evaluations/pfi-v2-core-20261026-r1 `
  --study-dir .rag-data/evaluations/qa-scoring-v3-dual-20261026-r1 `
  --gpt-dir .rag-data/evaluations/judge-gpt61sol-scoring-v3-core-20261026-r1-complete `
  --jev-dir .rag-data/evaluations/jev-openrouter-scoring-v3-core-20261026-r1-initial `
  --output-dir .rag-data/evaluations/qa-scoring-v3-dual-comparison-new
```

GPT先用`aggregate_qa_judges.py`核对并合并初评、失败补评及零调用结构复核；不能在两个有效分数中择优。对照工具再次复核原始API响应、源回答指纹和事先冻结的初始请求。Jev按保存的原生选择重建评分，保留原始状态与兼容性诊断。

默认必须两种裁判都覆盖全部计划题目。`--allow-incomplete`只能比较共同有效子集，明确列出排除项，不能把子集均分当成完整32题结果。

输出`comparison.json`包括：

- 各自必答要点均分和共有维度达标数，分别保留，不取平均作为最终质量分。
- 逐要点、事实支持、事实/范围分类、引用配对及引用组覆盖的分歧。
- 同为事实的引用一致率；事实/范围翻转另列，避免悄悄改变分母。
- 调用次数、已知用量、费用、请求耗时和失败状态。GPT实际账单未知时不估算。
- 完整一致题目和分歧题目清单，并从一致题中确定性抽取最多5题用于源文核对。

抽样按`SHA256(source_run_sha256:task_id)`排序，不人为挑看起来容易的题。抽样只表示选中了待核查样本，不代表完成专家校准或确认正确。

## 解释结果的边界

一致率不是准确率，两模型一致也可能都错。一次双评不能估计各自重复性；历史三轮使用旧规则，不能与本轮直接合并成同条件重复实验。

GPT仍评额外的边界、缺陷说明等字段并生成文字理由；Jev输出结构化选择。因此耗时是实际工作流程对照，不是等工作量的纯模型速度测试。

所有原始请求、回答和完整评阅保存在私有`.rag-data`，密钥单独保存。公开报告只保留统计、标签与来源指纹。正式分数由配置的外部裁判生成，开发助手只实现调用、校验、统计和单独标注的源文复核。
