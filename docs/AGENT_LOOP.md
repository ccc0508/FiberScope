# 有限Agent循环：独立实验入口

本版本自行实现Python调度层，使用Chat Completions原生Function Calling，不引入Agent框架。不改网站默认问答流程。

## 已实现

- 模型适配层将原生tool_calls转换成ToolCall(id/name/arguments)，工具结果反向转换成对应tool消息；DeepSeek思考续接字段只在运行内存中保留，不作为公开轨迹。
- 模型自主选择现有五种工具，沿用run级证据编号。图片工具返回原图像素，通过图像消息实际送给模型，轨迹保存图像载荷摘要及来源，不重复保存base64。
- 默认模型请求最多6次（含最终回答和复核）、工具尝试最多8次、总时限240秒、取证阶段预留45秒给收尾、单次输出8192 Token。
- 取证最多使用模型次数上限减2轮。达到工具/取证预算后禁用工具，请模型用已有证据回答并声明缺口，再在剩余时间内复核。
- 每轮最多执行一个工具：原生请求设置`parallel_tool_calls=false`，提示词也要求单次调用；若模型仍返回多个请求，只允许第一个执行，其余逐个回复`one_tool_per_turn`，不漏掉原生协议要求的工具响应。重复相同参数调用（忽略reason差异）被拒绝并计数；失败工具也计数。多余的未执行请求不消耗实际工具尝试数。
- 工具子进程采用剩余取证时间作为timeout。模型请求timeout不超过剩余总时限；CLI外层在总时限+5秒清理宽限后终止Windows进程树。
- 文本上下文默认最多160000字符，图像base64单独限制为24MiB。为草稿及复核保留空间：默认收集容量94464字符，达到86464字符停止继续取证。工具结果加入前再检查容量；若不能完整容纳，完整结果留库、明确通知模型未收到此结果，用已提供证据收尾。复核输入仍超限时保留初答并记录`skipped_context_budget`。这些字符预算是工程余量，不是精确模型Token计数或美元费用上限。
- 给模型的检索结果只包含最终补全正文、引用、来源定位和必要图片标识，不重复附上原始块全文。跨调用在同一文献内复用完全一致的文本行（至少80字符），通过T编号引用已发送原文；短行、数值变化和跨文献内容不模糊合并。相同证据快照只提示已提供，原[n]引用与后台不可变快照保持一致。部分重叠只有精确匹配的行被复用，不宣称语义相似去重。
- 每次收到结果后，提示模型检查必答事实、条件和不确定性是否足够；足够就作答，否则说明具体缺口。该证据充足判断由模型完成，并非程序保证。程序负责硬性的一轮一次和预算控制。
- 每次模型/工具执行前后保存状态：模型输入（不含隐藏推理、图片base64）、工具声明名称、输出、调用参数、用量、失败类型及停止原因。工具原文和统一证据另存原有数据库。
- 失败复核保留最近草稿并标记partial；若未生成答案则标记failed，不将截断当正常答案。

## 运行

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_literature_agent.py --question "论文的PFI条件是什么？" --library <文献库目录> --seconds 240 --max-tools 8 --max-model-calls 6
```

自动生成run_id，也可以指定`--run-id`；已存在的运行会拒绝，避免重放付费调用。状态保存在`.rag-data/agent-runs/<run_id>/state.json`，结束后导出evidence.json。异常中断记录保留，但不提供自动恢复或用户取消API。

当前是本地开发入口；未公开新HTTP接口、未接专家模式UI、未部署。引用内容正确性及图读数仍可能出错，预算限制不能替代评测。

### 2026-11-05：每题检索最多两次

AgentBudget.max_search_calls 默认2，允许1–2；这是单题整个Agent循环的检索执行上限，不是每轮上限。执行失败也占用次数；重复请求或同轮额外请求被拦截、没有实际执行时不占检索次数。达到上限后不再向模型提供search_literature；若模型仍请求，程序以search_budget拦截并记录轨迹。该拦截占总工具尝试预算，防止反复请求。

达到两次检索不会直接结束问答，仍可在原有总次数/时间/上下文预算内读取章节、表格、图片或计算，并完成回答和复核。state记录search_calls与max_search_calls。此前32题报告是修改前结果，不能视为两次检索版的评分。本次未重新调用付费模型评测，也未部署线上。
