# 有限跨子任务反馈

当前实现版本为 `specialists-v8-bounded-feedback`。首轮仍由 `route_task` 返回路由与原问题要求，程序负责启动子任务；首轮之后，Planner 可以通过原生工具协议额外调用一个子 Agent，整题最多补派一次。

## 执行顺序与结果传递

`Plan.dependency` 区分：

- `independent`：任务不依赖另一角色结果，继续顺序执行，不额外传入另一角色上下文。
- `sql_to_literature`：先查本地记录，将实际数值、单位、条件及原始工具证据传给文献 Agent，指导方法和适用范围核查。
- `literature_to_sql`：先核查论文方法，将已取得的条件和证据传给 SQL Agent，检查项目字段与记录是否具备。

子 Agent 继续返回结果、限制和逐项覆盖情况，并新增 `unresolved_items` 与 `next_information`。后者包含目标角色、原始需求编号、具体信息问题、必要性和已有证据编号，不能预填期望数值或科学结论。子 Agent 不能自行创建子任务。

## 最多一次补派

首轮有跨任务覆盖缺口，或子 Agent 明确提出所需信息时，且剩余调用、工具和时间预算足够，Planner 获得以下协议：

- `ask_sql_agent`：针对原问题中的 SQL 要求，或文献方法提出的本地数据前提补查。
- `ask_literature_agent`：针对原问题中的文献要求，或本地数据引出的文献适用条件补查。
- `finish_tasks`：证据足够、没有可用路径、需要用户澄清，或预算不足时结束。

补派必须指定真实的来源子任务、目标需求、待查问题、必要性和预期获取的信息。程序检查角色权限、原始需求编号和证据编号，不允许借补派引入新的研究目标。一次模型返回多个补派请求时不执行；补派失败仍占用这次机会，不能再转交给另一角色。

补派只能使用原任务已有的角色。跨角色核实前提时保留原需求的 `owner_role`，并标为 `prerequisite_only`；局部前提核实成功不代表原科学问题已完成，最终仍按原任务清单综合核对。

首轮已明确要求用户澄清时，不进行额外补派。无开放信息需求时直接进入综合；单一角色的普通覆盖缺口不自动升级为额外规划，除非显式返回 `next_information` 或 `unresolved_items`。

## 预算、证据与失败处理

- 不增加现有整题模型调用、工具、搜索或时间上限。
- 首轮联合任务在预算允许时，为反馈决策和一次补查保留调用额度；小预算优先保证首轮。
- 补派仅使用剩余额度，并为最终回答和必要的引用修正保留调用机会。
- 所有子任务沿用同一运行编号与证据账本，补派不重新编号。
- 只继承已经真实交付的工具结果，并受当前子任务上下文预算限制。未交付结果不成为可引用依据。
- 同一角色已成功且可复用的请求不会因补派重置去重；参数错误和临时失败继续遵守原有有限重试规则。
- 不传递原图像素；后续任务不能把继承的文字记录当作亲自看图。
- 可选补派或反馈决策失败时保留首轮有效材料，最终说明未解决项，不将整题直接归零。

## 轨迹与对照

运行状态记录 `task_schedule`、`feedback`、每个子任务的 `phase`、分配预算、继承证据及失败原因。Langfuse 通过精确 `child_id` 区分同一角色的首轮与补派。

命令行增加 `--no-task-feedback`，仅在 `--architecture specialists` 下使用，用于关闭当前代码的额外补派作对照。它不恢复旧版提示词或旧代码，因此不能将其称为完全相同的历史基线。

覆盖检查只验证证据可用性和任务状态，不证明陈述真实。某个子 Agent 自信地误读论文时，有限补派仍可能不触发；本次架构变化不能替代事实和引用语义核查。
