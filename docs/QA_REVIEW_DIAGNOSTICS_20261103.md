# 审校诊断与状态记录

本次只完善可观察性，不改变模型提示词、语义判断、评分规则、预算、重试次数或答案修改逻辑。未调用收费模型、未部署服务器。旧状态仍保留，新字段outcome用于解释状态而非覆盖它。

## 失败追踪

区分请求、输出截断、响应解析、诊断校验、修改校验及时间预算阶段。JSON语法错误记录行列和位置；字段错误记录字段路径及错误类型，不记录被拒绝字段值；已知封装错误记录固定错误码。requirements、claim_checks、relation_checks和comparison_checks的辅助条目校验不再仅记录泛化错误，保留具体字段信息。

运行应用时，输出截断、整体解析失败、部分诊断条目解析失败的原始文本返回保存在项目`.rag-data/review-diagnostics/<随机编号>.json`；重放脚本保存在该次输出的`private-diagnostics`目录。日志只含编号、哈希和保存状态，不含文件路径和原始返回；不记录API请求头、密钥或隐藏推理内容。文件创建用0600权限，Windows仍依赖目录继承ACL，不保证超出系统账户权限的隔离。私有目录不提交Git，也不设公开下载接口。目录写入失败只记write_failed，不改变原审校失败原因。

文件可能包含问题、论文片段及模型输出，需按私有业务数据管理；当前不自动清理，也不纳入公开报告。记录协议名与请求哈希，完整配置和源码指纹仍由既有运行快照提供。历史未保存的失败返回无法补回，不能以新日志解释过去未知的具体错误。

## 状态解释

每轮保留原始状态、错误、修改列表；最终outcome另外记录：

- 修改被拒绝、因来源未保留暂缓、已执行且最终答案中仍存在、执行后又变化/删除。
- 诊断错误属于历史轮次、当前记录，或原句已经变化需再次确认。
- 每个需求各轮的状态、原因和修改关联，以及最终未解决项。
- 始终声明语义未获独立验证，不将“已执行”自动等同于“已修好”。

第32题历史回放现在将原句comparison_statement_unsupported标为original_claim_changed_needs_recheck，而非直接当作最终原句仍错误；R2测量口径要求仍列未解决。整体状态仍incomplete。没有凭字符串变化自动关闭语义缺陷，也没有重新改写历史记录。
