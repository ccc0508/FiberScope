# 两版RAG完整流程的三轮稳定性验证

2026-10-31。复用已完成的第一轮，分别对内容组织85块版（content）和相同85块加候选重排版（rerank）各新增两轮。新增128份独立回答，连同历史64份，共形成两版×三轮×32题。

## 固定条件

- 沿用原封存baseline及各自私有配置、PDF、切块、向量、32道core_text题目与参考标准。
- 生成仍使用原DeepSeek别名、thinking/high参数，最多两次格式/引用纠正；Embedding、阈值、前8个主命中和上下文预算不变。
- 每道题由一个新的隔离工作进程执行完整的查询向量、检索、可选重排、上下文补全和生成流程。进程仅接收问题与独立数据目录，没有聊天历史、参考答案或旧评分。
- 新轮2按题让两版近同时各执行一次，等这一对完成后才执行下一题；轮3在轮2结束后开始。提交顺序按题交替，下一轮反转，最多两个答题进程并发。
- 原第一轮是在历史时间分别顺序运行，与新两轮的调度、缓存和环境不同。模型别名与参数固定不能证明远端模型权重未变；因此报告只给描述性稳定性结论。

## 问答与评分的区别

新增两轮是重新检索、重新重排和重新生成，不是给第一轮的同一份回答再打两遍分。

所有新增回答继续由Jev按原五维协议独立评分。原题目、参考答案、证据校验口径和评分提示词不改动。每个评分请求独立组装上下文，不附旧回答、旧评分或其他轮的评价；保留首个有效判定，最多三次请求，不选择最高分。新增Luna和DSH评分均为0。

评分沿用电脑已有HTTP代理，避免前一轮已确认的直连大请求上传故障；服务地址、裁判模型和评分请求内容不因代理而改变。费用将所有请求、失败尝试和未知费用分别记录。

完整答案保存后不自动重做，包括失败结果。中断但尚未收到结果的付费尝试需要先核对记录，不能直接重跑。

第3轮重排版第25题因两次引用校验未通过，返回了程序原有的拒答文本。该结果保留并交给Jev评分，不重新生成。原评测读取器尚未识别生产状态`refused`，因此增加独立读取兼容层，只校验身份、答案指纹和拒答结构，保持原状态、回答、检索证据及封存评分程序不变；兼容记录与程序指纹另存。

## 汇总规则

主稳定性比较使用两版×三轮全部六个组合都有有效且无参考标准异议的固定共同题集合。在相同题目集合上计算各轮五维指标、三轮等权平均、样本标准差和最小—最大值，避免因不同轮次缺失题目而产生假波动。

同时展示每一轮的最大共同有效题集合，完整列出32题的六份回答、评分及缺失原因。缺失不填零，不计算加权总分。逐题统计哪些必答要点或联合达标条件反复失败，哪些题只偶尔失败。

历史content第24题与rerank第23题的无效评分保持原样；不为扩大共同集合而补评。历史第11题存在Jev可能高估数值反例要点的问题，保留原判并披露，同时提供两版各轮统一排除该题的敏感性分析；此分析不替代人工核验，也不改变原分。

耗时和用量按版本、轮次分别记录。各题耗时的求和与两版并发执行的实际墙钟时间分开，缓存Token和货币费用未知情况保留原样。三轮小样本不足以证明统计显著性或新论文泛化。
