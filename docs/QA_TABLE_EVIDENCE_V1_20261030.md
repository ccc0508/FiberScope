# 表格行检索与正文—表格关联补全

2026-10-30。本轮以已完成局部复核的MinerU 95块索引为基础，不重新解析PDF、不重做局部视觉复核，也不修改正文切块参数。

## 改动

- 保留原95个证据块的ID、文字、类型、顺序和页码，以及主Chroma向量、原PDF及修正记录。
- 从2张完整HTML表格自动生成20条行检索表示。程序展开rowspan/colspan表头，保留列名、已有单位、(a)/(b)分组和对应原表题；所有120个数据单元格按原样取值。没有根据评测题补写数值或根据常识补单位。
- 行文本明确标注为程序生成的检索表示，带完整父表ID、页码和原始HTML行在父块中的字符范围。它只用于匹配问题，不直接作为原文引文送给答题模型。
- 每道题仍只生成1个BGE-M3/1024维问题向量。主Chroma检索最多50个候选；同一问题向量再与小型行向量索引进行精确余弦比较。行命中映射到完整父表，按父表最大余弦分数与主检索合并、去重，再保留最多50个不同父块候选。
- 仍使用0.35阈值、最多8个主命中。多行命中同一张表只占一个父表位置；没有增加独立重排模型、BM25或修改问题。
- 根据同文献正文中明确出现的Table 1/2等编号建立正文→表格关联；Table S1等补充表不会错误匹配为Table 1。完整表格反向关联最多2个直接讨论该表的附近正文块。当前共9条有向关联。
- 普通同页邻块补全后，从已实际提供的原文块出发补充关联表格或解释，允许跨页；不递归遍历新补入的内容。每条原证据最多补2个关联块，总计最多8个，单条8,000、全部24,000字符预算不变。预算不足时整块省略，不截断表格，不丢弃既有主命中。
- 新补入的表格或解释获得独立引用编号，页码取自身原始位置；记录触发关联、组成源块和原始种子ID。关联块沿用触发证据的分数，并明确该值不是独立检索评分。

这两项一起构成本轮优化；若评测变化，不能仅根据本次实验判断行检索与关联补全各自的独立贡献。

## 索引和运行

实验索引：`.rag-data/index-versions/table-evidence-v1-20261030`。

主证据95块不变，另存`table-retrieval.json`（20行、9关联和父表文字指纹）与`table-row-vectors.json`（私有向量）。原95块主索引直接复制，不重新向量化。本轮行Embedding共1次、4,836 Token，实际货币结算未知。

新增开关`RAG_TABLE_RETRIEVAL_ENABLED`，默认false；启用要求有界上下文补全也启用。独立实验配置在`.rag-data/configs`下；不修改网站默认配置。

冻结评测时同时封存行索引、向量及原修正记录，并验证父表内容、Embedding配置、向量维数及来源关联。程序遇到缺表头、无法确认表号、冲突合并单元格或跨文献关联时拒绝该构建/加载，不猜测来源。

当前行向量采用小规模精确扫描，适用于当前20行实验；大量文献入库后应迁移到可扩展的独立行向量集合，保留相同的父表映射和去重逻辑。行余弦与整块余弦采用最大值合并，没有进行概率校准，因此不把分数解释为正确率。

## 验证与边界

147项相关实现与回归测试通过，覆盖分组合并表头、行级定位、完整父表返回、跨页引用、跨文献拒绝、预算整块省略、一次问题Embedding和默认关闭。

本轮不改公式与变量定义的组织、不改参考文献检索分流、不加入视觉问答、不做正常区域抽查。章节路径和95块正文沿用前一版本；关键表格能否进入最终证据仍需实际检验，不保证任何单题一定改善。

答题模型、High档位、提示词和原32题、Jev五项评分标准不变。因为新增了检索逻辑，流程源文件指纹应变化，报告会显式检查变化仅在允许的检索与配置文件中，并单独核验答题提示词、生成器和引用校验代码保持一致。
