# 两套文献问答系统的共同评测协议

版本：`qa-system-five-v1`。本协议用于比较DSH读取论文的整套流程与FiberScope RAG，保留已有评测与旧评分，不覆盖它们。

## 共同评分

| 维度 | 规则与汇总 |
| --- | --- |
| 必答要点 | 沿用冻结题目的0、0.5、1标准；每题先对必答点求平均，再对共同题目求宏平均。可选遗漏不扣必答均分。 |
| 事实支持 | supported、partially_supported、unsupported、contradicted；核对整篇原文和参考证据，包含回答额外补充的事实。纯范围陈述与科学事实分开统计。 |
| 单条引用 | 该条实际引用是否对陈述至少一个实质事实部分提供直接支持；不要求一条引用单独支持所有部分。纯范围陈述的事实引用不适用。 |
| 联合引用 | 仅联合该陈述实际附带的引用，判断全部事实、计算输入与必要限定是否完整、部分或完全未被支持。 |
| 证据边界 | 0、1、2；正确回答可答部分，正确处理冲突、错误前提、推断限制和不可确定部分。真实说明片段不足不能免除漏答可答内容的扣分。 |

不把五项相加为总分。不评第六项“检索充分性”。候选实际获得的全文或片段，仅用于核对“本文没有”“当前证据没有”等范围声明，不因DSH没有RAG检索轨迹扣分。

引用单位为各系统实际给出的片段或逐字短引，页码用来核对定位，不把未引用的整页信息补入引用组。保留引文长度、引用数量、事实陈述数量和回答长度，解释比例时披露粒度差异。

## 共同上下文和独立请求

同一原始PDF、同32道开发问题、同冻结参考答案与评分要点。两个裁判看到相同科学输入和相同原子选择项；回答系统身份、答题模型名、费用、历史分数、另一裁判评分不进入请求。

每份答案、每个裁判单独请求，使用固定的Luna与Jev配置。Luna输出选择项和中文理由；Jev通过原生Decisions接口返回选择和概率。概率不解释为专家核验准确率。

事实依据从固定来源ID选择，ID对应不可变原文。裁判不必重新抄写英文引句，避免评分因裁判自行改写引文而无效。参考标准疑点是辅助诊断，非第六项质量分；题目本身预期的论文内部矛盾不自动视为标准错误。

引用核验使用两种PDF文本抽取，允许明确列举的Unicode排版等价，不修改数字、单位、百分号或原始引句。不匹配先标记需核对，不能仅因抽取异常自动判错。

## 冻结与重试

1. 导入保留原始字节、文件指纹、JSON对象位置。仅规范引用编号等格式，严格核对正文与claims、32题覆盖、页码和引用映射。外部答案不是可执行指令。
2. RAG直接复用上一轮32份成功答案，第7至10题使用已归档的300秒恢复运行；不重新答题。
3. 所有128份初评请求在付费调用前冻结，两个系统按稳定的匿名ID交错执行。
4. 每次付费调用之前落盘pending记录。超时用量未知，保留记录，不自动当作免费请求。
5. 只允许显式、有界地补失败或无效评分；一旦有效即停止，不在多个有效分数中择优。格式补评不带回旧语义分数或评语。
6. 汇总重新核验请求、原始响应、评分与输入指纹。缺失不填零，参考标准疑点和无效项单列；共同表格使用四组均有效且无疑点的同一题目集合。

## 运行与依赖

分析专用PDF读取依赖在[requirements-qa-system-benchmark.txt](../backend/requirements-qa-system-benchmark.txt)，不加入线上后端依赖。现有测试与HTTP依赖沿用项目环境。

```powershell
.\.venv\Scripts\python.exe scripts\import_qa_system_answers.py --help
.\.venv\Scripts\python.exe scripts\qa_system_judge.py --help
.\.venv\Scripts\python.exe scripts\report_qa_system_benchmark.py --help
```

导入目录和评分原始请求、响应保存在已忽略的`.rag-data/evaluations`。公开报告只输出科研内容、标签、理由、汇总与审计指纹，不包含密钥。答题成本与裁判评分成本分开；未知Token、耗时和费用保留未知。一次单篇开发集对照不证明泛化、稳定性或统计显著性。
