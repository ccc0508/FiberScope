# Jev独立评分接入

使用用户指定的OpenRouter账号，通过原生`POST https://openrouter.ai/api/alpha/decisions`调用`typesafe/jev-1.14`。它不是聊天补全接口，返回固定选项、概率和置信度，不生成自由文本评语。

## 当前新评分规则

新运行默认采用[统一评分标准v3](QA_SCORING_V3.md)，协议为`qa-jev-openrouter-v3`，与GPT使用相同规则和指纹。单条引用评实质贡献，新增引用组完整性；范围限制按实际检索核对。下文首次三轮实测使用旧v1协议，结果保持原样，不能与新规则混合汇总。

## 评分范围

本版对已保存的同一份完整回答评六个共同维度，不重新运行RAG或Embedding，不把GPT历史分数、理由、模型身份、耗时或费用发给Jev：

| 维度 | 原子问题与输出 |
| --- | --- |
| 要点覆盖 | 每个适用要点独立选遗漏、部分、完整，程序固定映射为0、0.5、1；可选点与必答点分开 |
| 事实支持 | 每条陈述选支持、部分支持、无依据、矛盾，并另行区分科学事实与纯范围声明 |
| 单条引用有效性 | 每个陈述—实际检索引用配对判断是否直接贡献一个具体事实 |
| 引用组完整性 | 整组判断是否覆盖全部事实，不能用未引用片段、全文或标准证据补救 |
| 证据边界判断 | 整体回答是否符合题目要求的回答、部分回答、拒答或冲突说明，映射为0/1/2 |
| 检索充分性 | 每个适用要点只根据实际检索判完整/部分/缺失，不适用项单列 |

程序预先从实际检索结果、固定标准证据和完整论文生成原文片段编号；Jev选择编号，程序回填不可变原句并复核来源。找不到单条依据可以选择`NONE`，记录为证据未定位，不编造引句。纯范围声明可选择全文/文库范围核查。

每道评测题独立提交，同一次请求批量判断各评分项；程序据事实/范围分类排除纯范围引用，原始引用判断仍保留。`shared_dimensions_pass`保留前四个维度的标签达标口径，证据定位完成率另列；它**不等于GPT完整评分中的严格达标**，也不是专家正确性认证。
新协议把引用组完整性纳入引用维度；有一条有用引用不再自动表示整条事实陈述被覆盖。
本版不补写模型未生成的理由，不把缺失的人工关键错误说明或标准答案专家校核字段伪装为已评。

## 私有配置

模板：[backend/.env.jev.example](../backend/.env.jev.example)。私有配置`backend/.env.jev`被Git忽略，不复用回答模型或GPT裁判的密钥。

```dotenv
QA_JEV_BASE_URL=https://openrouter.ai/api
QA_JEV_MODEL=typesafe/jev-1.14
QA_JEV_API_KEY=在私有文件填写OpenRouter密钥
QA_JEV_TIMEOUT_SECONDS=120
```

保留OpenRouter返回的具体模型版本、供应商及请求编号；关闭供应商回退。模型别名不在本次评测中使用。不同运行若实际模型版本改变，比较工具须明确报告，不能混成同版本重复评分。

## 六维度对齐（2026-10-27）

新增证据边界与逐要点检索充分性，默认协议升为 `qa-jev-openrouter-v3`；评分语义标准仍为 `qa-scoring-v3`，题目和原回答不变。

| 维度 | 原生输出与解释 |
| --- | --- |
| 必答要点完整性 | missing/partial/complete 映射 0/0.5/1 |
| 陈述事实支持 | supported/partially_supported/unsupported/contradicted |
| 单条引用有效性 | supported/unsupported 映射 1/0；纯范围陈述不适用 |
| 引用组完整性 | complete/partial/missing；纯范围陈述不适用 |
| 证据边界判断 | incorrect/partial/appropriate 映射 0/1/2，直接使用与 Luna 相同的 rubric.answerability_scores 定义 |
| 检索充分性 | 每个适用要点 complete/partial/missing，只检查 candidate.retrieved_evidence；实验预设不适用项固定 not_applicable |

以第四题为例，旧请求含 28 个判断项，新请求增加 1 个边界判断和 3 个检索判断，共 32 项，仍是每题一次应用层请求。新判断由 Jev 返回，程序不根据要点分或 Luna 结果推算。全文与标准证据只能定义核查目标，不能补全实际检索中缺失的内容。

`shared_dimensions_pass` 保持原四项口径；新增 `boundary_aware_pass` 要求四项达标且边界为 2。检索充分性作为诊断单列，统计完整/部分/缺失和适用数量，不与答案分数相加，也不把不适用项当成完整。比较结果只有双方全部题目均提供后两项时才标 `six_dimensions`，否则明确为四项共有维度，并列出未能比较的维度。

保留 `qa_jev_prompt_v2.py` 用于按原协议重建旧请求。旧评分不增加虚构字段，不覆盖旧记录；新运行必须用新目录。旧第四题上下文示例仍忠实反映旧协议，不是新版请求。Jev 仍不输出自由文本理由、人工关键错误诊断、参考答案专家核验或完整 strict pass；六个维度对齐不等于两个评委返回的所有字段都一致。

新版已完成32题真实评分，32次调用全部有效，无补评；与既有Luna结果完成六维度对照，详见[六维度重新评分报告](QA_JEV_SIX_DIMENSIONS_20261027.md)。旧报告仍保留原四项共有维度口径。

## 运行与恢复

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/judge_qa_jev.py --run-dir .rag-data/evaluations/pfi-v2-core-20261026-r1 --output-dir .rag-data/evaluations/jev-new-round --limit 1
```

先限制1次真实调用检查接口；同一目录继续运行会核对源回答、请求、实际工具和已保存的有效决策，跳过已处理项。`--limit`最多100次，默认1次。正式三轮使用三个独立目录，固定模型、题集、完整原回答、同一证据和问题定义；不传会话编号或前轮评分。

每次付费请求前保存`pending`和请求指纹，原始请求保存在`requests/`、原响应和决策保存在`tasks/`，每个运行另存`harness/`、`jev-run.json`、`reviews.jsonl`及`progress.json`。未知中断、HTTP失败和不合格响应不会自动重放；鉴权、余额或权限错误立即停止新增请求。

只有全部选定任务均有效且实际模型版本一致，才生成该运行的`summary.json`。原有GPT评分、题集和RAG代码保持独立，失败不记作答案0分。

## 用量、时间与比较口径

- 记录所有响应的输入/输出Token、原生`usage.cost`（美元）、请求耗时及失败状态；无用量或费用的失败保持未知，不按0处理。API报告费用与实际充值账单分开。
- 原生输出没有总Token时，仅在输入和输出均已知时计算二者之和。
- 单条回答一次请求批量评其原子问题；按整个回答统计耗时，保留中位数、P95和失败数。
- 三轮Jev互相比较同一任务的要点、事实、引用与概率波动；与GPT仅比较共有维度，分数和意见分别保存，不能把GPT一致率称作Jev正确率。
- 历史GPT流程评维度更多、还生成文字解释，且执行时段不同。费用/时间对照只代表这些实际流程的历史参考，不是同等输出和负载下的严格模型基准。
- GPT代理服务实际账单未知时不估算其扣费，也不宣称节省了某个百分比。

当前完整论文、标准证据与原文候选一起输入，可能触发OpenRouter自动启用的长上下文模式；其影响需要在本题集实测，不沿用短请求的官网延迟作为本项目结果。中文问答与纤维术语也需要领域校准。

官方资料：[Jev接入说明](https://openrouter.ai/docs/guides/community/jev)、[Decisions API](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request)、[模型及价格](https://openrouter.ai/typesafe/jev-1.14)、[Choice类型](https://docs.typesafe.ai/primitives/choice)。

## 首次三轮实测与兼容性复核

2026-10-26已执行96次调用，三轮分别得到32条可读取评分，必答要点均分88.02%、88.02%、88.54%。OpenRouter报告费用合计0.268660476美元，各轮单题请求中位耗时约0.9秒。详见[实测报告](QA_JEV_EVALUATION_20261026.md)。

原始适配器先接收30、28、28条，另外10条保留为原始`invalid_response`。离线复核只处理两种接口兼容性：概率两位小数合计0.99时的浮点容差，以及一个辅助证据选项与报告最高概率项不一致的诊断。前者不归一化原始概率，后者保留原选项并加显式标记；核心评分项的选择不享有这种例外。未新增模型调用，也未改动任何模型评分或旧输出。

`compare_qa_jev.py`只读复核三个Jev目录、三个历史GPT目录及冻结研究契约；验证原始请求/响应、源回答与历史工具指纹，再重建类型化决策、统计共有维度、调用费用和累计请求耗时。新解码器及逐项诊断另存分析harness，原始评分工具仍保留在`d646e1a96da162ebc3344069f4b97c164770ef6e`版本。
