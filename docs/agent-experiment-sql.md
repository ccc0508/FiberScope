## 基线问题修复与EXPLAIN预检

歧义影响统计结果时先澄清阈值、指标或粒度，不擅选最高档位；使用JOIN/EXISTS确认样本集合，不能只凭计数相等判断集合相同；字段限制不得扩展到无关指标。以上行为由答题和复核提示约束，不宣称程序能自动证明统计口径正确。

结果新增result_state（empty/rows_returned/truncated）；0行提示只代表精确条件未命中，一行NULL聚合不代表一个观测，截断结果须保持原筛选在SQL聚合。SQLGlot为ROUND(AVG)自动插入的数值CAST允许穿透单位来源，用户显式CAST仍不支持。

所有查询先经AST白名单，然后在同一只读事务中运行EXPLAIN(FORMAT JSON)，不使用ANALYZE。总估计成本超过1,000,000或任一计划节点估计行数超过1,000,000时拒绝执行；这两个值是初始保守保护阈值，不是秒数或准确资源预测。顺序扫描不单独拒绝，原5秒语句超时和1秒锁等待保护保留。返回精简计划摘要，不暴露底层完整计划；预检不能证明业务口径正确。20条参考SQL全部通过，当前最大成本42.6、节点估计行数255。

失败记录增加failure_stage，区分validation/explain/execute。AST拒绝返回实际不支持节点（如case/cast）；数据库错误分类覆盖类型、输入值、分组、除零、取消/超时、锁等待和标量子查询多行。错误提示不得建议擅自改筛选、用0替代不可计算结果或LIMIT 1掩盖多行。失败不产生引用。

## 按记录类型引用与编号纠正

成功的 source_text、source_image、experiment_query、calculation 记录可引用；目录、字段说明、失败或被阻止的调用仅留调用轨迹，不产生引用编号。成功工具结果保存 citation_records，发给模型时明确列出可引用编号与类型。编号仍由现有 run 内证据账本分配，不按调用次数计数。

答案复核结束（或失败保留初稿）后，程序检查数字引用、分组/范围引用及误用内部ID。只允许本次实际送达模型的成功证据编号，预算不足而未发送的结果不可引用。无效时至多调用一次 citation_repair，沿用原时间、上下文及模型调用预算，不再调用工具；要求根据实际证据改正引用，缺少依据时删除可选结论或说明缺口，不可机械替换编号。

修正仍不通过或无预算时，答案置空并返回失败，原答案和修正尝试保存在 citation_validation.attempts。网页适配边界还会对照持久化账本再检查，避免静默丢弃无效引用。此检查仅证明引用编号存在且类型允许，不证明对应陈述受原文支持；不会恢复此前关闭的结构化内容审校校验。

验证：95项相关测试通过。真实 DeepSeek Agent 试答先调用两次目录、再调用一次 SQL，查询出针叶28、阔叶24、混配9、总计61；最终只引用实验查询的 [1]，编号检查通过且没有额外纠正调用。未重跑30题文献回归集。

## SQL 结果的列单位

查询返回 `column_metadata`，与 `columns`、行数组按从0开始的 `position` 对齐，包含中文含义、单位、确认状态及可追溯的源字段。重复别名仍按位置区分。真实字段目录用于解析来源，不能通过将列命名为某指标来冒用单位。

直接字段、星号展开、派生表别名及 AVG/SUM/MIN/MAX/ROUND/ABS 等保留源单位；COUNT 标为计数，不自动解释成样本数。暂定和未确认单位保持原状态。算术表达式、COALESCE、标量子查询等暂不自动推断单位，明确返回未确认；解析不确定时不猜测。

SQL 结果不再附加通用 NOTES。百分数存储说明仅随百分比列返回，其他列不会携带无关百分比备注。该元数据随结果进入证据快照；目录工具仍保留现有说明。87项相关测试及3组真实数据库查询通过，未重跑文献评测集。

新增 `describe_experiment_data`（真实字段目录、单位、统计粒度）与 `query_experiment_data`（受限 SQL）。模型生成 SQL，程序解析、校验后重新生成 PostgreSQL SQL，再交给数据库执行。

## 字段错误反馈

PostgreSQL 42703（字段不存在）和42702（字段歧义）返回独立错误码、请求字段、相关查询作用域的视图/别名、当前视图内相近字段，以及真实包含该字段的白名单视图。字段名只接受提交SQL语法树中出现的标识符；不回传原始数据库异常。失败事务退出后使用新只读连接读取目录；诊断失败时保留原失败状态，不影响原查询结果。

这些建议不会自动替换字段、切换视图或放宽条件，模型仍受现有工具/时间预算限制。零行是成功结果。派生表仅提示检查其输出别名，不凭空推断继承字段；无法可靠提取出错字段时返回目录核对提示。未改变引用策略，未增加EXPLAIN。

当前允许 catalog.py 中八个 fiber 分析视图之间的任意连接，包括自连接、内外连接、交叉连接和 LATERAL SELECT；支持标量子查询、派生表、IN/EXISTS 及相关子查询。无需预先定义连接组合或连接键。支持筛选、排序、GROUP BY/HAVING，以及 COUNT、SUM、AVG、MIN、MAX、ROUND、ABS、COALESCE、NULLIF。仍不支持 CTE、集合操作（如 UNION）、类型转换或任意函数。

程序检查整棵语法树：所有层级的实际视图引用均须在白名单内，省略 schema 的白名单视图会补为 fiber；每层 LIMIT/OFFSET 都验证。不能通过子查询绕过函数、写入或系统表限制。执行重新生成的 SQL，不直接执行原始字符串。连接后的统计粒度由模型根据字段目录判断，程序不会保证任意连接在业务上合理；一对多连接可能重复计数，应在正确粒度聚合或去重。

沿用应用专用只读连接，事务只读，查询超时 5 秒、锁等待 1 秒；search_path 限定 pg_catalog。服务端游标最多读取 101 行，返回最多 100 行、约 24000 字符的行数据；截断时明确返回 truncated。统计全体数据应使用数据库聚合，不可根据截断结果推算全体。

SQL、列名、行数据、查询时间、全部涉及视图（包含子查询中的视图）及限制说明保存为 experiment_query 证据快照，分配当前回答内统一引用编号。网页显示实验数据库来源，不生成论文页码或 PDF 链接。来源追溯可连接 v_data_lineage；该视图一行是一项来源用途，不能把行数当作样本数。
