# 检索诊断方法与统计边界

2026-10-30。复用原32道核心文本题，已完成PyMuPDF结构81块、MinerU原生117块、MinerU章节107块三套封存索引的检索诊断，见[结果报告](QA_RETRIEVAL_DIAGNOSTIC_20261030.md)。此阶段不优化或切换索引，不重新答题、不调用评分模型、不修改原评测集或历史评分。

## 采集流程

1. 核验三套基线、原始答题记录、相同题目与检索设置，复制索引到独立私有目录。
2. 原问题仅去掉首尾空白，一批调用BGE-M3/1024维生成32个向量，三套索引共用这些向量。成功缓存有指纹，重复执行不会自动重复收费；失败或中断需先检查。
3. 使用各自原封存后端的`RetrievalService`，仅包裹向量库的`search`方法记录全部50候选，再原样返回候选。继续使用原0.35阈值、前8主命中、同页邻块半径1和8,000/24,000字符预算。
4. 重放进程只接收问题、缓存向量、检索设置和本地路径，不接收标准答案、参考证据或历史回答。标准证据仅在事后诊断中对齐。
5. 核对重放前8和最终上下文是否与历史一致。50候选是本次采集的重放结果，不能冒充历史答题时实际记录的50候选。

执行入口：[diagnose_qa_retrieval.py](../scripts/diagnose_qa_retrieval.py)。依次运行`prepare`、`embed`、`replay`、`report`；报告可用`refresh`离线重建。

## 原文定位与覆盖

- PyMuPDF使用重建原页的字符范围；MinerU使用原生块及字符范围。章节107块使用已保存的组成片段映射，程序添加的章节标签不算原文命中。
- 搜索视图只作NFKC、空白和公开的排版别名归一化，原始文字不改写。相同页码或相同关键词不能直接算引文齐全。
- 表格按同页表号及全部标注数据行的数值顺序定位。目前四项表格标注各有5行、30个数值；这确认同一表格对象的位置，不等于判断回答已经充分使用该表。
- 近似文字锚点记录差异、匹配比例及数字差异，单列待核查；无法可靠定位的标注记“待定位”，不记为检索失败。
- 定位引文被拆在多个检索块时，计算其全部来源范围的联合覆盖；重复或重叠块不重复累计。
- “首次交集排名”只表示部分位置进入候选，“齐全排名”表示累计候选覆盖完整定位范围，两者分开报告。

## 汇总口径

跨索引汇总只使用三套索引共同严格定位的引文，并按“题目×关联引文”去重，保持相同分母。同一表格可能支撑多条标注，这些请求不视为独立实验。范围、语料库边界和测试边界类要点不参与原文位置覆盖评分；仍展示检索轨迹与历史答案供审阅。

标注引文可能比回答所需信息更长，存在其他可用证据时也可能未被标注。因此该覆盖率不是答案正确率、语义充分性、全部相关证据召回率或新的正式评分维度。近似映射不混入共同严格汇总。

私有缓存保存在`.rag-data/retrieval-diagnostics/retrieval-diagnostic-v1-20261030`；不导出密钥或问题向量。源索引、原答题记录和应用默认配置保持不变。
