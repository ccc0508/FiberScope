# MinerU：仅改写检索与改写重排

2026-11-02。用户要求不再用原问题检索，且重排也使用改写问题。本轮在MinerU候选版增加rewrite_only模式；dual模式和默认关闭行为保留。

## 流程和控制变量

对照：原问题Embedding → 最多50候选 → 原问题重排 → 最多8主命中 → 原上下文补全 → 回答原问题。

试验：原问题 → 原DeepSeek改写一次 → 仅改写Embedding → 最多50候选 → 同一改写重排 → 最多8主命中 → 原上下文补全 → 回答原问题。

试验组不调用原问题Embedding，不进行原问题向量搜索，不融合两路候选，不使用RRF。若改写文本恰好与原问题相同，仍记为一个改写分支。若改写调用失败、格式无效、超长或丢失受保护数字/标识符，直接记录失败，不偷偷回退到原问题检索。最终生成器继续使用原问题，不把改写当作论文证据。

同一条改写贯穿检索和重排。原提示词、改写模型与参数、JSON结构和校验规则不变：DeepSeek现有路由，关闭思考，temperature=0，最多768输出Token，30秒，不重试。每题记录实际改写、分支、重排输入、用量、异常和模型返回信息。改写由模型实时生成，不复用上一轮文本；与上一轮双路结果比较时不能假定改写完全一致。

其余均固定：同一原PDF、MinerU分类113块、BGE-M3 1024维、Chroma、20条表格行表示、10条关联、0.35阈值、BGE重排模型、可靠小节与明确表号补全、8000/24000字符预算、DeepSeek回答High思考。回答指引关闭，不重解析或重建文献向量。

## 试验

两组各32次新答题，固定同一源提交、数据与共享配置，只改变是否开启rewrite_only策略。两组并行启动，各组按题序执行；每题新进程，只传原问题和论文库，不传金标准、旧回答或分数。题目从UTF-8文件读取。

本轮同时改变检索与重排输入，测试的是组合策略，不能将差异拆成某一环节的独立贡献。网络、模型别名及生成随机性无法冻结；一轮单篇论文开发集不代表稳定性或泛化。

Jev沿用原qa-system-five-v1协议和原设置，每份回答独立组装评分上下文，只接受首次有效原判。最多3次尝试，无效请求计入费用，评分缺失不记零；共同有效、无标准答案疑点的题目用于总体对比。两组均保留全部32题答案，不手工改分或挑选答案，不新增Luna/DSH调用。

对照、试验均重新测量，不直接复用上一轮分数。分别报告五维、全达标、失败数、候选/主命中/最终输入变化、用量和耗时。记录首次生成输入相同的题，避免把这类题的分数波动归因于检索改善。供应商未返回的货币费用为未知，不重复相加推理Token。

## 配置与存储

- RAG_QUERY_REWRITE_ENABLED=true
- RAG_QUERY_REWRITE_MODE=rewrite_only
- 仍要求已配置DeepSeek与重排；复用私有凭据，不新增密钥。
- 私有运行：.rag-data/evaluations/pfi-rewrite-only-original-20261102-r1及pfi-rewrite-only-rewrite-20261102-r1。
- 评分：.rag-data/evaluations/rewrite-only-20261102。

代码从干净独立检出封存，保留用户正在编辑的前端内容。网站默认配置和服务器不切换。
