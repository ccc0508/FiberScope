# Ubuntu服务器迁移验收

迁移开始于2026-10-24，夜间完成。平台通过`/fiberscope/`挂载到现有HTTP站点，保持原根路径网站及443服务可用。
用户选择先使用HTTP，尚未配置域名与HTTPS；入口必须使用`http://服务器公网IP:80/fiberscope/`。

## 环境与结构

- Ubuntu 24.04.2，x86_64；约1.6GiB可见内存、40GB磁盘，已有2GB交换空间。
- 新增独立系统用户`fiberscope`，应用目录`/opt/fiberscope/`，持久数据`/var/lib/fiberscope/`。
- Python 3.12.3及项目锁定的文献依赖；PostgreSQL 18.6；现有Nginx作为反向代理。
- 后端仅监听127.0.0.1:8010，数据库仅本机访问；实际应用账号是独立随机密码的fiber_app，禁止底层表读取和实验数据写入。
- 单个API worker，问答和提取分别保持单任务限制。设置数值库线程及应用内存上限，避免挤占同机其他服务。
- 模型与Embedding继续调用原有API，服务器不运行本地大模型。

  该归档不是本次新生成的源库dump，因此另外使用本机当前只读查询作为参照，比对八个分析视图的完整内容。
- 八个视图的行数及规范化内容SHA-256全部与源库一致：samples=61、beating=52、blends=11、fiber-paper=61、
  recycled/cycles=47、recycled/details=131、quality=4、lineage=257。
- 迁移完整`.rag-data`，包含1篇14页的问答论文、44个片段及向量、3条原问答、9个提取任务、PDF、检查点和审核版本。
- SQLite使用在线备份，包含已提交WAL数据；复制76个数据文件后校验SHA-256及四份SQLite的完整性。
- 私有配置通过SSH传输到`/etc/fiberscope/`，权限root:fiberscope 0640；未将密码、API密钥、真实论文或问答记录提交Git。
- 后续服务器和本机是独立的数据副本。服务器新增的记录需要纳入服务器备份，不会自动回传到本机。

## 部署适配

- 前端统一使用构建BASE_URL生成路由、接口、PDF、页预览、导出和图标地址，根路径开发仍兼容。
- Nginx将`/fiberscope/api/`转发到后端`/api/`，改写Cookie路径，覆盖转发Host和协议，保持Origin检查。
- 保留原站点配置备份，测试Nginx配置成功后reload；原网站HTTP 200，原443服务保持运行。
- CORS测试原先固定localhost；改为验证实际配置的允许来源，以便同时验收本机及服务器配置。
- 反向代理、systemd及备份配置见`deploy/ubuntu/`。
